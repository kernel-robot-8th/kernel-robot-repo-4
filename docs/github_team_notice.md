# 팀 GitHub 사용 안내

**담당 분야 브랜치에서 작업하고, submaster에서 함께 확인한 뒤 main에 반영합니다.**

담당 분야 브랜치 → submaster에서 함께 확인 → main에 반영

- main과 submaster는 팀 공통 코드입니다. 직접 올리지 않고 PR로 합칩니다.
- `feature/vision`, `feature/navigation`처럼 기존 담당 분야 브랜치는 계속 사용합니다. 작은 작업마다 새 브랜치를 만들 필요는 없습니다.
- 새 분야 브랜치가 필요하면 최신 submaster에서 만들고, PR 대상은 submaster로 선택합니다. 오래된 분야 브랜치는 담당자가 최신 코드와 차이를 확인한 뒤 반영합니다.
- 코드와 테스트·필요한 문서를 같이 올리고, 작성자 외 한 명 이상 확인을 받습니다.
- 기존 PR은 작성자가 변경 내용을 확인한 뒤 대상을 바꿉니다. 다른 사람 브랜치는 임의로 수정하지 않습니다.
- 합쳐졌거나 사용이 끝난 브랜치는 반영 여부를 확인하고 담당자와 정리합니다. 아직 반영되지 않은 작업은 지우지 않습니다.

## 브랜치 이름

기본은 `feature/담당분야`입니다. 필요할 때 작업 내용을 덧붙입니다. 메뉴 번호는 팀 공통 필수 규칙이 아닙니다.

- 분야별 작업: `feature/vision`, `feature/navigation`, `feature/gui`
- 별도 기능이 필요할 때: `feature/gui-robot-cards`
- 오류 수정: `fix/navigation-docking`

이미 쓰는 브랜치 이름은 이 공지 때문에 바꾸지 않아도 됩니다.

## 커밋 제목

관련된 변경을 한 묶음으로 저장하고, 제목 앞에 용도를 붙입니다.

- `feat`: 새 기능 — `feat(gui): 로봇 상태 카드 추가`
- `fix`: 오류 수정 — `fix(gui): 상태 표시 오류 수정`
- `docs`: 문서 — `docs(common): 설치 안내 수정`
- `test`: 테스트 추가·수정
- `refactor`: 기능은 그대로 두고 코드 정리
- `chore`: 개발 설정·의존성 등 관리 작업

기능 수정과 메모 데이터는 나눠 커밋합니다. 비밀번호·토큰·개인 설정·빌드 결과물은 올리지 않습니다.

데이터셋·큰 모델 파일은 가능하면 Hugging Face 등 외부 저장소에 두고, Git에는 링크와 사용법을 공유합니다. 이미 올라간 팀원 자료를 임의로 삭제하지 않습니다.

**커밋 = 내 PC에 저장 / push = GitHub에 업로드 / PR = 팀 코드에 합쳐 달라는 요청**

submaster는 2026-10-24 최신 main과 같은 코드로 생성했습니다. 브랜치 보호 설정은 별도 적용이 남아 있으므로 위 규칙을 지켜 주세요.
