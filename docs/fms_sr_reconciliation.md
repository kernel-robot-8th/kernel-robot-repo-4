# SR 정본 대조와 설계 제안 분리

- 조회일: 2026-10-22. 정본: [Confluence SR_v2](https://pinkyteam4.atlassian.net/wiki/spaces/PinkyTeam4/pages/5406727/SR_v2), version 13, 수정일 2026-10-21.
- 조회 방식: 연결된 Confluence의 현재 원문 직접 읽기. HTML 장식 일부가 제거된 Markdown에서 표의 ID·이름·우선순위를 대조했다. 앞뒤 공백과 zero-width 공백만 정리했다.
- 레지스트리·검사기·시험은 SR-01~22의 동일한 이름·우선순위·순서를 검사한다. 메뉴 목록의 정본은 계속 메뉴 레지스트리다.
- 이 대조는 요구사항 변경 승인이나 실물 검증이 아니다. D1~D5·D8은 proposed 상태를 유지한다.

## 원문에서 확인한 차이

| 항목 | SR_v2 v13 원문 | 옛 v5.0/기존 설계와의 처리 |
|---|---|---|
| SR-08 정차 | 목표 오차 0.01 m, 각도 15도 이내, 위치조정 3회 후 fail | ±5 cm를 SR 요구값으로 인용하지 않는다. 맵 접근점·팔 도킹 계약에 1 cm·15도·3회 기준을 별도로 반영해야 한다. |
| SR-19 제어권 | 제어 컴퓨터 단일화, 통신 채널 분리, 통로·주문 중앙 관리 | 10/12 번호, 두 rclpy Context, 온보드 가드는 팀 설계 제안이다. 도메인만 다르다는 이유로 인증·제어권 안전을 증명하지 않는다. |
| SR-20 명령 | 세션 번호·유효시간 5초, 재시작·복구 때 세션 갱신 | seq·서명·map_hash·구체 거부 코드는 설계 계약이다. 원문에 모두 있다고 쓰지 않는다. |
| SR-21 증거 | ACK와 실제 센서 완료 구분, 실행 이력 보존 | 실제 센서가 없으면 미계측이다. 스키마 시험과 가짜 센서는 물리 완료의 증명이 아니다. |
| SR-22 | 가상환경 시뮬레이션 및 사전 검증 기능 (신규 롤) | 메뉴 6.5를 SR-22에 연결했다. 실제 2.4×2.4 m 경기장·로봇과의 정합, 주행·도킹·상하차·간섭 시험은 별도 실행 증거가 필요하다. |
| 우선순위 | R/O 외에 SR-02는 RO(DB), SR-15는 빈칸 | 원문을 보존한다. 빈칸을 임의로 필수/선택으로 채우지 않는다. 해석은 팀 결정으로 남긴다. |

## 결정과 구현을 막는 대조 항목

1. D2·D11: 10/12 도메인, 200 ms 워치독, ±50 ms 시계 허용치는 설계 제안으로 담당 검토한다. 개발 100/101 및 localhost 격리 스파이크는 실물 설정 적용과 구분한다.
2. D3: 67 cm 게이트 맵·정차점과 SR-08을 함께 검증한다. 6 cm 맵 린트 반경은 로봇 footprint·선회·팔 고정대 충돌 검증이 아니다. 맵 hash 일치도 같은 지도를 읽었다는 증거에 한정된다.
3. D4·D5: 정지 예외, 재개·복구 승인 절차는 SR-11·13·14의 요구를 구체화한 제안이다. SR 원문 또는 공지 없는 자동 확정값으로 쓰지 않는다.
4. D6: 팔 끝 Z=280 mm·특정 센서·HW 릴레이 설치 여부는 별도 설계·실측이다. 현장 출발 조건과 센서 증거를 정하기 전에는 미계측을 PASS로 승격하지 않는다.
5. D17: SR-22 존재 여부는 조회로 해소했다. 메뉴 원문의 개수·3.7 처리·메뉴별 의미 매핑과 SR-15 빈 우선순위는 아직 팀 확인 대상이다. 문구상의 'SR-22 미등록'만으로 작업을 막지 않는다.

이후 정본이 바뀌면 version을 먼저 갱신하고 레지스트리, 코드의 SR_CANON, 시험의 AGREED_SR, 이 대조표를 같은 PR에서 고친다. 옛 v5.0 문서는 역사 자료로 보존하며 현재 요구사항보다 우선하지 않는다.
