팀이 함께 쓰는 메시지 양식(msg/srv/action)을 어느 패키지에 둘까? 패키지 이름 접두사는 무엇으로 할까?

### 지금 상황

- 미병합 브랜치 `feature/setup-fleet-msgs-structure` 에 `fleet_msgs` 가 있다 (msg 3개, action 2개, srv 없음). main 에는 아직 인터페이스 패키지가 없다.
- `FleetCommand.msg` 에는 epoch·seq·TTL·map_hash·command_id 가 없다. 그래서 SR-20 명령 유효성 확인 및 옛날 권한 차단 기능을 표현하지 못한다.
- `FleetCommand.msg` 는 team11 `pinky_fleet_msgs`(Apache-2.0)에서 왔다. 그런데 `package.xml` 에 원저작 표기가 없다.
- main 의 폴더 이름은 `cobot_navigation`, `cobot_vision` 이다. CLAUDE.md 는 `<proj>_<역할>` 자리표시자만 둔다.

### 선택지

| 안 | 내용 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| 1안 (추천) | `fleet_msgs` 를 `cobot_interfaces` 로 옮기고 확장한다. 접두사는 `cobot_` 로 한다. | CLAUDE.md §2 의 `<proj>_interfaces` 자리와 맞는다. 쓰는 코드가 아직 없어 지금 옮기는 비용이 가장 낮다. | 미병합 브랜치 작성자와 맞춰야 한다. |
| 2안 | `fleet_msgs` 이름 그대로 병합하고 확장만 한다. | 브랜치를 그대로 쓴다. | CLAUDE.md §3-1 '패키지명은 `<proj>_<역할>`' 과 다르다. 나중에 바꾸면 쓰는 패키지를 모두 고쳐야 한다. |
| 3안 | 인터페이스 정리를 S2 뒤로 미룬다. | 지금 할 일이 준다. | 규칙 R3(인터페이스 먼저) 때문에 S2 이후 작업이 모두 막힌다. |

### 추천안

1안. `fleet_msgs` 5종을 `cobot_interfaces` 로 옮기고 SR 이 요구하는 필드를 더한다. 접두사는 `cobot_` 로 정한다. team11 `pinky_fleet_msgs`(Apache-2.0) 원저작 표기를 복원한다.

### 이유

- CLAUDE.md §2·§3-1: 공용 msg/srv/action 은 `<proj>_interfaces` 에 두고, 패키지명은 `<proj>_<역할>` 이다.
- CLAUDE.md §3-4·§9: 양식을 바꾸면 쓰는 패키지가 모두 영향을 받는다. 쓰는 곳이 없는 지금이 가장 싸다.
- SR_v2 SR-20는 세션 번호와 유효시간 5초, 재시작·복구 때 세션 갱신을 요구한다. seq·map_hash·서명은 별도 설계 제안이다. v1 FleetCommand에는 이를 표현할 자리가 없다.
- Apache-2.0 은 원저작 고지를 남기라고 한다 (라이선스 §4).

### 결과 (바뀌는 파일·PR, 예정)

- `feature/common-cobot-interfaces`: `src/cobot_interfaces/` 신설. `fleet_msgs` 이전, 확장 메시지, 원저작 표기, 스키마 시험(S1 출구 검사 2).
- `feature/common-team-rules-s1`: CLAUDE.md §2 구조도·담당표의 `<proj>` 자리를 `cobot` 으로 적는다 (S0 에서 미룬 일).
- 미병합 브랜치 `feature/setup-fleet-msgs-structure` 는 건드리지 않는다. 닫을지는 그 브랜치 작성자가 정한다.
- 파일 목록은 각 PR 설명이 정본이다. PR 이 열리면 이 줄을 PR 링크로 바꾼다.

### 되돌리는 방법

S2 착수 전이면 `feature/common-cobot-interfaces` 를 revert 한다. 쓰는 코드가 아직 없다. S2 뒤에는 쓰는 패키지의 import 와 `package.xml` 의존을 함께 고쳐야 하므로 비용이 커진다.

## D2 ROS_DOMAIN_ID

- 상태: `proposed`
- 결정자: (공지 때 관제 담당이 채운다)
- 결정일: (공지 때 관제 담당이 채운다)
- 막는 단계: 모든 노드 발견 (S1 이후 전부)

### 질문

실물 장비는 어떤 `ROS_DOMAIN_ID` 를 쓰나? 두 도메인은 어디에서 만나나? README 의 100 은 무엇으로 두나?

### 지금 상황

- SR_v2 SR-19는 통신 채널 분리와 단일 제어권을 요구하지만 ROS 도메인 번호 10·12는 지정하지 않는다. 10·12는 옛 v5.0에서 가져온 팀 설계 제안이다.
- README §4 는 팀 공통 값으로 `export ROS_DOMAIN_ID=100` 을 적었다.
- 둘이 다르다. 도메인이 섞이면 핑키 3대의 토픽이 서로 간섭할 수 있다.

### 선택지

| 안 | 내용 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| 1안 (추천) | 팀 설계 제안. 10 = 실물 구동(관제·가드·팔의 명령과 상태), 12 = Nav2. 두 도메인의 교차점은 핑키 온보드 가드 노드 하나다. 가드가 rclpy Context 를 둘 연다. README 의 100 = 개발·시뮬 전용. | 요구사항의 채널 분리를 구현하는 후보안이다. 명령이 지나는 길이 가드 하나라 단일 기록자가 분명하다. | 두 Context 방식이 Jazzy rclpy 에서 되는지 아직 확인하지 않았다. |
| 2안 | 10·12 를 `domain_bridge` 로 잇는다. | 표준 도구다. | 브리지 설정 파일이 교차 토픽 목록의 정본이 된다. 명령 토픽이 브리지를 타면 명령 경로가 둘이 된다. |
| 3안 | 도메인 하나(예: 100)로 실물까지 쓴다. | 설정이 가장 쉽다. | SR-19 의 도메인 분리와 다르다. 채널 분리와 단일 제어권을 만족시키는 대안 검토가 먼저다. |

### 추천안

1안.

- 두 Context 방식은 S1 스파이크로 확인한다 (주행 담당과 함께). 결과를 이 절에 적는다.
- 스파이크가 실패하면 2안으로 바꾸되 명령 토픽은 브리지에 넣지 않는다. 이 절을 고치고 다시 공지한다.
- 100 은 개발·시뮬 전용이다. 개발 PC 의 가짜 발행기와 시뮬이 쓴다. 실물(10·12)과 섞지 않는다.
- 개발용 도커 컨테이너(빌드·시험용)는 도메인을 정하지 않는다. 바깥과 막혀 있어 도메인 값과 상관없이 실물과 섞이지 않는다 (아래 '결과' 절).

### 이유

- SR_v2 SR-19의 단일 제어권 요구를 만족시키려는 설계 제안이다. 온보드 가드·10/12 번호·두 Context 방식은 SR 원문이 아니라 구현 선택이다.
- CLAUDE.md §7: GUI·관제가 별도 PC 에서 돌면 `ROS_DOMAIN_ID` 와 네임스페이스 규칙을 `docs/` 에 적는다.
- CLAUDE.md §9: `ROS_DOMAIN_ID` 는 임의로 바꾸지 않는다. 그래서 이 결정과 공지로 바꾼다. 실물 장비에 값을 넣는 일은 현장 실측(D18) 뒤에 사람이 한다.
- 시뮬을 실물과 다른 도메인에 두면 로드맵 S6 출구 검사 3(시뮬 launch 가 실물 도메인이면 기동 거부)과도 맞는다.

### 추천안

질문 1, 2 모두 1안. 순단마다 사람 승인이 들어 운영 부담이 클 수 있다. S2 에서 순단 빈도를 잰 뒤 SR 개정을 요청할지 다시 본다.

### 이유

- 정지를 거부해서 더 안전해지는 경우는 없다.
- SR_v2 SR-20: 재시작·통신 복구 시 세션 번호 갱신과 옛 명령 폐기를 요구한다. epoch +1과 워치독 미갱신 방식은 추가 설계 제안이다.

| 4안 | 확인 버튼 두 번 | 쉽다. | 두 단계 사이에 독립 요소가 없다. 버린다. |

### 추천안

1안을 기본으로 둔다. 2안·3안은 설정으로 켤 수 있게 한다.

- 이 방식이 SR-14 를 충족하는지는 팀이 정한다. 이 문서는 SR 의 뜻을 바꾸지 않는다.
- 5 s 같은 시간 값은 초안이다. 확정은 D11(시간 값)에서 한다.

### 이유

- SR_v2 SR-14에는 Reconcile·2단계 승인 문구가 없다. 여기서는 장애 대응을 구체화하는 추가 설계로 제안하며, 현재 정본을 충족하는지 팀이 검토한다.
- SR-21 실제 동작 센서 확인 및 이력 기록 기능: 관제사의 확인 입력이 원장에 남아 나중에 거슬러 찾을 수 있다.
- README 팀 구성 표: 관제 담당 1명. 2인 승인을 기본으로 두기 어렵다.

### 결과 (바뀌는 파일·PR, 예정)

- `feature/common-cobot-interfaces`: 운영 명령 서비스에 확인 입력(`attest`)과 거부 코드(초안 이름 `ATTEST_MISMATCH`, `APPROVAL_DWELL`)를 넣는다.

### 되돌리는 방법

## D8 웹 정적 자원 위치

- 결정자: (공지 때 관제 담당이 채운다)

### 질문

웹 화면의 정적 파일(HTML·JS·CSS)을 어느 패키지·폴더에 두나?

### 지금 상황

- CLAUDE.md §3-1 은 '한 패키지는 한 가지 언어'(ament_python 또는 ament_cmake)와 표준 폴더 목록만 정한다. 웹 자원 자리가 없다.
- CLAUDE.md §9 는 규칙 밖 새 폴더와 허락 없는 새 의존성을 막는다.
- 그래서 지금 규칙만으로는 어느 안도 안 된다. 규칙 개정이 필요하다.

### 선택지

| 안 | 내용 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| 1안 | 별도 패키지 `cobot_gui_web` (정적 파일 전용) | 언어가 섞이지 않는다. | ament_python·ament_cmake 어디에도 맞지 않는 새 패키지 형태다. 패키지가 늘고, launch 가 정적 파일 경로를 넘겨야 한다. |
| 2안 (추천) | `cobot_gui`(ament_python) 안 `web/` 폴더를 `setup.py` `data_files` 로 설치 | 패키지 수가 그대로다. 설치 방식이 CLAUDE.md §3-2 의 `data_files` 그대로다. 화면 담당이 패키지 하나만 본다. | Python 패키지 안에 JS 가 들어간다. 그래서 §3 에 규칙을 더해야 한다. |

### 추천안

2안. CLAUDE.md §3 에 이런 규칙을 더한다: '`web/` 은 웹 화면 소스 폴더다. 빌드 결과 `web/dist` 만 `setup.py` `data_files` 로 install 하고 커밋하지 않는다. TypeScript 는 브라우저 화면 소스이고 ROS 실행 코드가 아니다. 실행 코드의 언어는 패키지 언어 하나다.' 문구는 규칙 PR 에서 정한다. 지금 CLAUDE.md §3-7 초안의 '따로 빌드하지 않는다' 와 'vendoring' 문구는 이에 맞게 고친다.

D8 후속 (이번 결정 범위 밖, S2 착수 전에 따로 정한다):

- 웹 서버 라이브러리 fastapi·uvicorn 사용 허락.
- 프론트 도구: 홈랩 관리자 화면과 같은 구조(React·react-router·Vite·Tailwind)를 쓰고, 빌드는 Node/npm 으로 한다. 패키지 목록과 라이선스는 `docs/fms_web_dependencies.md`(자동 생성)에 있다. 버전은 `package-lock.json` 이 고정하고 설치는 `npm ci` 로만 한다. 사용 허락은 관제 담당이 팀에 설명하고 받는다.
- 설치 방법 후보는 apt 패키지 또는 `python3 -m venv --system-site-packages` 다 (CLAUDE.md §5). apt 패키지가 있는지는 아직 확인하지 않았다.
- S1 출구 검사 5 는 D8 의 이번 범위(패키지 형태와 폴더 규칙)만 본다.

### 이유

- CLAUDE.md §3-1: 한 패키지 한 언어, 표준 폴더 목록.
- CLAUDE.md §3-2: `config/`·`launch/` 는 `data_files` 로 등록해야 install 된다. 같은 방식을 `web/` 에 쓴다.
- CLAUDE.md §9: 규칙 밖 폴더와 허락 없는 새 의존성은 금지다. 그래서 규칙 개정과 의존성 허락을 먼저 받는다.
- 규칙 R4: 화면 정적 파일 자리는 정해지기 전에는 만들지 않는다.

### 결과 (바뀌는 파일·PR, 예정)

- `feature/common-team-rules-s1`: CLAUDE.md §3 에 `web/` 폴더 규칙을 더한다.
- `feature/gui-common-web-shell`: `web/` 화면 골격(메뉴 34개 틀)과 생성기. 개인 레포에서 먼저 검증한 뒤 팀 레포에 올린다. 머지는 규칙 개정과 Node 허락 뒤에 한다.
- 파일 목록은 PR 설명이 정본이다.

### 되돌리는 방법

S2 초반이면 `web/` 을 새 패키지로 옮기고 `data_files` 줄을 그 패키지로 옮긴다. 화면 코드가 정적 파일 경로를 파라미터로 받게 짜 두면 옮기기 쉽다.

## SR 원문 대조 후 유지되는 미결

SR 정본 조회와 결정 승인은 다르다. 도메인 10/12, 시계 ±50 ms, 워치독 200 ms, 팔 Z=280 mm, 정차 공차, 승인 5초, 정지 계열 서명 예외는 팀 설계 제안이며 관련 담당 리뷰가 필요하다. `docs/fms_sr_reconciliation.md`와 저장소 보호 상태를 함께 확인한 뒤 결정을 갱신한다.
