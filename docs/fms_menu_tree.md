## 읽는 법

- 메뉴 하나 = 작업 단위 하나다. 레지스트리에 없는 화면·도구는 만들지 않는다.
- 단계(phase)는 그 메뉴 작업이 처음 시작되는 단계다. 뒤 단계 범위는 메모에 있다.
- 메모에서 '초안:' 으로 시작하는 줄은 판단이 들어간 값이다. 팀 확인 전이다.
- SR 칸의 ✱ 는 메뉴 트리 원문과 SR 매핑이 다른 메뉴다. 원문 값과 이유는 그 메뉴의 상세에 있다.
- 결정 상태: `open` 은 미결, `proposed` 는 추천안이 있고 공지 전, `decided` 는 공지했고 결정자·날짜를 적은 것이다. `decided` 만 정해진 것으로 본다. 기록: `docs/fms_decisions.md`
- 초안: 메뉴 수는 34개로 센다. 원문 본문의 '33개' 는 3.7 을 넣기 전 숫자로 본다. 작성자 확인 전이다 (D17).
- 아키텍처 설계서 v0.1 은 아직 팀에 공개하지 않은 초안이다. 그래서 판단 근거는 설계서 절 번호 대신 각 메뉴 메모에 직접 적었다.
- 개인 담당자는 2026-10-24 사용자 지정이다. 메뉴별 화면·데이터 계약 경계는 담당자가 확인하고, 로봇 기능 개발과 관제 구현을 구분한다.
- 2026-10-24 사용자 지정: 로봇 수행 관제는 김지혜, 이상 감지 관제는 강건한. 주행 김진호, 로봇팔 강민석·김성아·허지석, 비전 손선아·강건한.
- 초안: 메뉴별 decisions 는 설계서 §10.1 의 막는 것 열에서 옮겼다. 각 결정이 막는 것은 생성 문서의 결정 목록 표에 있다.
- SR 매핑은 메뉴 트리 원문 대조표를 따랐다. 원문과 다른 메뉴는 sr_original 에 원문 값을 두고 메모에 이유를 적었다. UR ID 는 sr 에 넣지 않는다.
- 패키지 접두사 `cobot_` 는 main 의 폴더 이름(`cobot_navigation`, `cobot_vision`)을 따랐다. README 의 `<proj>_` 는 자리표시자다. 확정은 D1.
- 역할의 packages는 기술 영역이다. gui·control_center는 공유하며 개인 책임은 메뉴의 control_owner와 사용자 담당표를 따른다.

#### 1.1 전체 로봇 현황

- 데이터 원천: RobotStatus v2, ArmStatus, ArmMode
- 명령: 없음
- ✱ 원문 SR: SR-06, SR-09 (지금 매핑과 다르다. 이유는 아래 메모)
- 갱신: 5 Hz 합류. 원천 시각 기준 1 s 를 넘으면 STALE(회색).
- P1 은 기존 RobotStatus(v1) 필드로 먼저 돈다. 이때 데이터 나이 기준은 v1 timestamp 다.
- 초안: SR-09 로봇팔 상차·하차 기능을 빼고 SR-10 적재 및 작업 완료 확인 기능, SR-12 로봇팔 안전 제어 기능을 더했다. 팔 카드는 팔 동작이 아니라 퇴피·적재 확인과 안전 정지 상태를 보인다. SR-06 로봇 상태 모니터링 기능은 핑키 상태를 다룬다.
- 초안: 데이터 담당은 핑키 카드 기준이다. 팔 카드(ArmStatus·ArmMode)는 manipulation 이 낸다.

#### 1.2 작업·미션 현황

- 데이터 원천: OrderStatus, 팔 작업 단계 요약, InventoryState
- 명령: 없음
- ✱ 원문 SR: SR-01, SR-18 (지금 매핑과 다르다. 이유는 아래 메모)
- 갱신: 변화가 생기면 바로 보낸다.

- SR-18 6단계와 QR 결과·재고 가점유 상태(SR-02)를 보인다.
- 초안: SR-02 재고 및 대상 박스 확인 기능을 더했다. 원문에는 SR-02 를 보이는 메뉴가 없었다.

#### 1.3 로봇 할당 현황

- 데이터 원천: Assignment, UnloadQueue
- 명령: 없음
- 갱신: 변화가 생기면 바로 보낸다.
- 수동 재배정 버튼은 두지 않는다.
- 배정 제외 사유(SR-03)와 하차 FIFO(SR-16)를 보인다.

#### 1.4 알림·이벤트 센터

- 갱신: 변화가 생기면 바로 보낸다.
- 알림 확인은 잠금 해제가 아니다.
- 초안: SR-02 재고 및 대상 박스 확인 기능을 더했다. QR 이 주문 상품과 다를 때의 알림을 이 메뉴에 띄운다.

#### 2.1 통합 주행 지도

- 데이터 원천: MapInfo, 지도 PNG, RobotStatus pose, LaneLeaseState
- 명령: 없음
- 갱신: 위치 5 Hz, lease 는 변화가 생기면 바로.
- 원문의 '67 cm 게이트' 는 맵 정본(D3 추천안)의 게이트다. 중앙 벽 아래 Y 0~0.67 m. 장애물 랙 2 가 벽에 붙어 있어 창고 쪽 실제 통행은 0.45 m 이고 게이트 정차점은 [1.25, 0.225] 다.
- map_hash 가 맞지 않으면 RED.
- 초안: 데이터 담당은 위치·맵 기준이다. lease는 control_center가 낸다. 항공뷰는 위치·도킹 정본으로 사용하지 않는다.

#### 2.2 로봇별 주행 상태

- 데이터 원천: RobotStatus v2
- 명령: 없음
- ② 지도의 인스펙터 패널이다.
- 갱신: 5 Hz.
- P1 은 v1 필드로 먼저 돈다. v2 필드(도킹 오차·BASE_HOLD, SR-08)는 P2.

#### 2.3 목표점·경로 관리

- 데이터 원천: MapInfo.waypoints
- 명령: 없음
- ② 지도 위 레이어다. 읽기 전용이다.
- 웨이포인트는 패키지 config YAML 을 PR 로 고쳐서 바꾼다. 화면에서 고치지 않는다.
- 갱신: 기동할 때.
- 접근 자세가 없는 웨이포인트에는 경고를 띄운다.

#### 2.4 주행 미션 관리

- 데이터 원천: OrderStatus, CommandAck, CompletionEvidence
- 명령: 웨이포인트 미션 보내기 (관제사 + 콘솔 + MANUAL), 미션 취소
- ✱ 원문 SR: SR-04, SR-17 (지금 매핑과 다르다. 이유는 아래 메모)
- 갱신: 변화가 생기면 바로 보낸다.
- 원시 좌표는 보내지 않는다. 배정·lease 를 거친다.
- ACK·물리 증거(CommandAck·CompletionEvidence)는 navigation 이 낸다.
- 초안: SR-17 빈 박스 및 반품 회수 관리 기능을 뺐다. 우선순위 R 이고, 회수는 이후 단계(S6)에서 다룬다. 회수 화면을 정할 때(D14) 다시 넣는다.
- 초안: 데이터 담당은 미션을 내는 control_center 로 두었다.

#### 2.5 주행 이력·이상 상태

- 데이터 원천: QueryAudit (주행 이벤트), AlarmEvent
- 명령: 없음

- 통합 전 조건 (docs/fms_branch_compatibility_review.md): 팔 배타 제어(ArmMode LEROBOT_EXCLUSIVE), Servo OFF 는 긴급 정지가 아니다(정상 종료와 정지를 나눈다), 실행 환경 차이(Ubuntu 22.04 + 별도 LeRobot 환경, D18).

- 명령: 소프트 정지 래치 (토큰 불필요), RESET, Reconcile 항목별 확인, 승인(APPROVE), START
- 함께 보이는 화면: ①
- ① 헤더에는 정지 버튼, ⑤ 에는 복구 절차를 둔다.
- RESET 은 START 가 아니다. RESET → Reconcile → 승인 → 최소 체류 → START 순서다.
- 초안: 주 화면을 ⑤ 로 두었다.

#### 5.5 안전·장애 상태 모니터링

- 명령: 없음
- ✱ 원문 SR: SR-11, SR-12, SR-14 (지금 매핑과 다르다. 이유는 아래 메모)
- 갱신: 변화가 생기면 바로 + 2 Hz.

- 3회 재시도는 오류 유형별이다. 통신 두절은 즉시 로컬 정지다.
- HW E-STOP 배지와 전원 증거는 다른 행으로 보인다.
- 초안: SR-10 적재 및 작업 완료 확인 기능을 더했다. 팔 퇴피(ARM_RETRACT_SAFE) 확인은 핑키 출발을 막는 인터록이므로 안전 상태로 함께 보인다.
