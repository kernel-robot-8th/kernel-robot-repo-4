# 수집 의도를 반영한 재학습·공식 LeRobot 학습

## 이번에 바꾼 기준

사용자가 지정한 수집 역할을 따른다. **0~10번은 기본 시연, 11~14번은 DAgger 느낌의 보완 시연**이다. 이전의 ‘10~14번 전체를 최종 테스트로 보관’한 해석을 이번 학습에 적용하지 않는다.

물체 개수와 수집 역할은 별도 정보다. 영상 0~9번에서는 박스 2개, 10~14번에서는 1개가 보인다. 10번은 사용자 지정에 따라 기본 수집에 넣는다. 같은 에피소드라는 표현은 동일 태스크의 별도 반복 녹화로 우선 해석했다. 15개 녹화의 수집 시각이 다르고, 움직이는 100프레임 구간 12,807개의 상태·행동 해시 검사에서 녹화 사이의 완전 중복은 없었다. 한 원본 녹화를 나눈 조각이라는 추가 정보가 확인되면 원본 단위로 재그룹해야 한다.

보완 시연을 정식 DAgger의 정책 실행·전문가 개입 로그로 단정하지 않는다. 이번 작업은 사용자 지정 보완 시연을 학습에 포함했을 때의 효과를 비교하는 것이다.

## 실제로 실행하는 학습

| 구분 | 실제 실행 | 조건 |
|---|---|---|
| 경량 비교 48건 | 기존 모방학습 루프 | CNN·경량 ACT × 기본만/보완 결합/보완 균형 샘플링 × 4회 분리 × 시드 17·42 |
| 공식 ACT 비교 8건 | `python -m lerobot.scripts.lerobot_train` | 기본만/보완 결합 × 같은 4회 분리, 시드 17 |
| 전체 데이터 재학습 2건 | 경량 후보·공식 ACT 각각 | 0~14번 전체를 학습에 사용, 별도 독립 테스트 없음 |

공식 학습 루프 파일은 수정하지 않았다. 설치된 LeRobot 버전과 학습 스크립트 SHA256, 실제 명령·로그·최종 설정을 기록한다. 모델이나 데이터셋을 자동 공개 업로드하지 않는다. 가중치는 Git 외부에 저장한다.

## 기본·보완 시연을 어떻게 나누는가

공통 기본 학습 ID는 `[0,1,2,3,4,5,6,7,10]`, 기본 검증은 `[8]`, 기본 평가는 `[9]`다.

| 회차 | 보완 학습에 추가 가능한 ID | 보완 검증 ID | 보완 평가 ID |
|---|---|---|---|
| 0 | 13, 14 | 12 | 11 |
| 1 | 11, 14 | 13 | 12 |
| 2 | 11, 12 | 14 | 13 |
| 3 | 12, 13 | 11 | 14 |

기본만 학습한 대조군도 같은 검증·평가 ID를 쓴다. 보완 데이터를 합치는 모델은 각 회차의 보완 학습 2개를 추가하고, 검증·평가용 보완 ID는 학습하지 않는다. 검증의 기본·보완 녹화가 각 1개여서 녹화별 평균 MAE가 수집군 50:50 검증 기준이 된다.

보완 균형 샘플링은 **학습 표본을 기본군 50%, 보완군 50% 확률로** 뽑는다. 각 군 안에서는 녹화별 확률을 같게 한다. 단순 결합은 모든 학습 관측 프레임을 섞는다. 두 설정의 차이를 별도로 기록한다.

정규화 통계는 매 모델의 학습 ID만으로 계산한다. 공식 학습기의 경우 원본 영상·행동 파일을 그대로 가리키는 로컬 데이터 사본을 만들고, `meta/stats.json`만 해당 학습 녹화의 공식 집계 통계로 교체한다. 공식 `eval_split`이 지정한 두 검증 ID를 정확히 골랐는지 학습 전에 검사한다. 평가 ID는 공식 학습 입력 목록에서도 제외한다.

## 파라미터 설명과 실제 값

| 항목 | 경량 비교 | 공식 LeRobot ACT | 의미·차이 |
|---|---|---|---|
| 학습 루프 | `cobot_mujoco.train` | 수정하지 않은 `lerobot.scripts.lerobot_train` | 실행 코드가 다르며 공식 명령·로그를 별도 보존 |
| 이미지 | RGB 128×96, 두 카메라 | **원본 RGB 640×480, 두 카메라** | 영상 세부 정보와 계산량이 다름 |
| ACT 내부 폭 | 128 | **기본값 512** | 변환기가 표현하는 특징 크기 |
| ACT 중간 폭 | 512 | **기본값 3,200** | 변환기 내부 순방향 신경망 크기 |
| ACT 인코더·디코더 | 2층·1층 | **기본값 4층·1층** | 신경망 깊이 |
| ACT 잠재 인코더 | 2층, 잠재 크기 32 | **기본값 4층, 잠재 크기 32** | 시연의 잠재 표현, 검증·추론 시 잠재값 0 |
| ACT 학습 가중치 수 | 실행 모델에서 집계 | **51,597,190개 확인** | 정규화 버퍼·최적화 상태를 제외한 학습 숫자 수 |
| 행동 예측 길이 | 16스텝 | **기본값 100스텝** | 30Hz에서 약 0.53초/3.33초 미래 목표값 예측 |
| 재예측 전 실행 길이 | 5스텝 | 기본값 100스텝 | 추론 설정이며 학습 손실 자체를 바꾸는 값은 아님 |
| 배치 크기 | 24 | **8** | 가중치를 한 번 갱신할 때 쓰는 관측 표본 수 |
| 학습률 | CNN 0.0003 / ACT 0.0001 | **ACT 기본값 0.00001** | 가중치 갱신 크기; 양쪽 모두 이 실험에서는 스케줄러 없음 |
| 가중치 감쇠 | 0.0001 | 기본값 0.0001 | 큰 가중치 억제를 위한 AdamW 규제 |
| dropout | 0.1 | 기본값 0.1 | 학습 중 일부 활성값 무작위 제외, 평가에서는 끔 |
| 영상 인코더 | CNN은 자체 합성곱 / ACT는 ResNet18 | 기본 ResNet18 | ACT는 양쪽 모두 ImageNet 초기값 사용 |
| 영상 증강·입력 노이즈 | 끔 | 끔 | 데이터 추가·샘플링 효과를 비교하기 위한 고정 조건 |
| 관측 표본 | 학습 시작점 3프레임 간격 | 원본 프레임 사용 | 미래 행동 목표 간격은 양쪽 모두 30Hz |
| 정규화 | 학습 ID 평균·표준편차, 표준편차 최소 1 | 공식 전처리기·학습 ID 통계·ImageNet 영상 통계 | 두 파이프라인의 정규화 구현도 다름 |
| 손실 | CNN L1 / ACT L1+KL | 공식 ACT L1+KL, KL 가중치 10 | 에피소드 끝 패딩 제외, 검증 선택은 별도 공통 지표 |
| 최대 단계 | 20,000 | **10,000** | 실제 종료·저장 단계와 구분; 공식 구조를 경량화한 것이 아님 |
| 종료 | 250스텝마다 검증, 0.005 초과 개선이 10회 없으면 최소 1,500스텝 뒤 조기 종료 | 공식 고정 단계 루프, 1,000스텝마다 저장·검증 | 공식 루프를 조기 종료 방식으로 고치지 않음 |
| 작업 시간 상한 | 작업당 600초 | 작업당 2,400초 | 상한에 걸리면 저장된 실제 단계와 제한 상태를 기록 |
| 전체 시간 | 최대 12시간, 마무리 90분 확보 | 동일 감독 프로세스 | 계획이 먼저 끝나면 종료하며 12시간을 억지로 채우지 않음 |

기본 시연 9개와 보완 포함 11개는 **녹화 수**이며 물체 개수가 아니다. 시드 17·42는 새 현장 녹화를 추가하지 않는다. 구조·해상도·표본 수·학습률·학습량이 동시에 다르므로 공식/경량 결과 차이를 모델 크기 하나의 효과로 설명하지 않는다.

## 선택·평가·전체 데이터 재학습

1. 각 모델은 검증 녹화의 **앞 10개 미래 행동에 대한 녹화별 평균 MAE**로 체크포인트를 고른다. 공식 학습은 실제 저장된 기본 체크포인트를 별도 검증기로 읽어 같은 지표를 계산한다.
2. 데이터 사용 방법과 최종 경량 설정은 검증 점수만으로 정하고 파일에 고정한 뒤, 각 모델 학습에 들어가지 않은 기본 9번·보완 1개를 평가한다.
3. 보완 평가는 같은 녹화의 시드 평균을 먼저 낸 다음 **고유 녹화 4개**를 평균한다. 신뢰구간도 녹화 단위로 계산한다. 기본 평가는 독립 녹화가 1개뿐이라 일반적 성공률이나 좁은 신뢰구간을 주장하지 않는다.
4. 이번 자료는 이미 검토한 수집 데이터이므로 새로 수집한 독립 현장 테스트라고 표현하지 않는다. 4회 분리도 서로 겹치는 학습 자료를 사용하는 탐색적 검증이다.
5. 마지막으로 검증에서 선택한 단계 수를 사용해 경량 후보와 공식 ACT를 **0~14번 전체로 각각 재학습**한다. 보완 11~14번을 모두 넣는다. 이 최종 후보에는 독립 테스트가 남지 않으므로 테스트 점수를 붙이지 않는다.

공식 최종 후보는 기본 Hugging Face/LeRobot `pretrained_model` 디렉터리와 전처리·후처리기를 보존한다. 경량 후보는 `final.pt`와 정규화 JSON을 보존한다. 실제 경로는 보고서에 표시한다.

## 실행·상태·중단·결과

```bash
scripts/mujoco/run_retraining.sh
cat ~/omx_sim_runs/retraining_20261025/status.json
```

같은 실행 폴더의 완료 작업은 다시 학습하지 않는다. 공식 학습 작업이 이미 실행 중이면 감독기가 해당 PID를 인계해 기다린다. 중단 시 공식 학습기와 자식 작업을 함께 종료하며, 공식 체크포인트가 있으면 원래 `--resume` 기능으로 재개한다. 최초 설정·종료 시각을 보존한다. 평가를 연 뒤에는 학습 설정을 바꾸지 않는다.

```bash
~/venv/omx_mujoco/bin/python -m cobot_mujoco.cli stop \
  --run ~/omx_sim_runs/retraining_20261025
```

현재 보고서는 [`docs/mujoco_validation/report.html`](../../../docs/mujoco_validation/report.html), 재학습 근거 JSON은 `docs/mujoco_validation/retraining_20261025/`에 저장한다. 1차 보고서는 `round1_report.html`에 보존한다. 종료 후 결과와 보고서를 같은 MuJoCo 브랜치에 한국어 커밋으로 자동 푸시한다. 실행 중 종료 시각·실제 완료 개수를 표시한다.

## MuJoCo의 남은 한계

기본 박스 수는 2개로 수정했지만 성공 시연 명령의 물리 재생이 아직 배치를 재현하지 못한다. 이번 재학습의 효능을 보정 전 정책 성공률 0회로 판단하지 않는다. 실측 치수·카메라·접촉·모터 응답 보정을 거쳐 실제 성공 시연을 재현한 뒤 물리 성공률 검증을 진행해야 한다. 실제 로봇은 이 실행기에 연결하지 않는다.

## 디스코드 30분 진행 알림

사용자 요청에 따라 로컬 사용자 타이머 `omx-retraining-discord.timer`가 30분마다
`cobot_mujoco.progress_notify`를 실행한다. 기존 웹훅 파일
`~/.local/share/codex-discord/webhook`을 읽으며 웹훅 주소는 Git·로그·명령 인자에 넣지 않는다.
누적 시간, 실제 완료 건수, 현재 작업·스텝, 감독기·학습기 생존 상태를 전송한다.
직전 알림과 작업·스텝이 같으면 변화 없음 문구를 추가한다. Discord 응답의 메시지 ID를
실행 폴더 `discord_notification.json`에 기록해 전달 성공을 확인한다.

정기 확인에서 전체 실행 종료를 확인하면 최종 상태를 보내고 타이머를 자동 해제한다.
감독기 중단도 알림에 표시하며, 12시간 상한 이후 1시간이 지났고 감독기도 종료된 경우에는
마지막 상태를 보내고 알림을 멈춘다. 이 타이머는 현재 PC의 사용자 세션에서 동작한다.

```bash
systemctl --user list-timers --all omx-retraining-discord.timer
journalctl --user -u omx-retraining-discord.service -n 10 --no-pager
systemctl --user disable --now omx-retraining-discord.timer  # 알림만 중단
```
