# LeRobot 0.4.4 ACT 일반형·경량형 학습·검증

사용자 요청에 따라 `~/il_ws/src/lerobot`의 **LeRobot 0.4.4 원본 학습 코드**를 사용한다.
Python은 `~/venv/il/bin/python`이다. 기존 0.6.1 가중치를 변환하거나 이어서 학습하는 방식이 아니라
ACT를 새로 학습한다. 영상 인코더는 양쪽 모두 ImageNet ResNet18 초기값을 사용한다.
독립 CNN 정책, MuJoCo, 실물 로봇 실행은 포함하지 않는다.

## 구조와 공통 조건

| 항목 | 일반형 ACT | 경량형 ACT |
|---|---|---|
| 영상 입력 | 카메라 top·wrist 각각 RGB 640×480 | 동일 |
| 영상 인코더 | ResNet18, 학습 중 가중치 갱신 | 동일 |
| Transformer 폭 / FF 폭 | 512 / 3,200 | 128 / 512 |
| 관측 인코더 / VAE 인코더 | 4층 / 4층 | 2층 / 2층 |
| 디코더 / 헤드 / 잠재 크기 | 1층 / 8개 / 32 | 동일 |
| 배치 / 난수 시드 | 8 / 17 | 동일 |
| 기본 주 학습률 / ResNet 학습률 | 0.00001 / 0.00001 | 동일 |
| 기본 가중치 감쇠 / dropout / KL | 0.0001 / 0.1 / 10 | 동일 |

경량형은 Transformer를 줄이며 해상도·ResNet18을 유지한다. 따라서 총 파라미터 수는 줄지만
영상 처리 비용은 그대로 남아 속도·메모리가 같은 비율로 줄어든다고 보장하지 않는다.
원본 학습 루프·최적화·저장은 바꾸지 않았다. 버전·소스 경로·Git commit·train과 ACT 소스 SHA256을 기록한다.

## 실험 계획: 12개 학습 경로, 44개 저장 시점 비교

1. 구조 2개 × chunk 16·32·64·100 = 8개 경로를 최대 20,000스텝 학습한다.
   각 경로에서 2,000·5,000·10,000·20,000스텝 저장본 4개를 검증한다.
2. 구조별 chunk 32 기준에서 **주 학습률만** 0.00003으로 바꾼 경로를 10,000스텝 학습한다.
3. 구조별 chunk 32 기준에서 **감쇠만** 0.001로 바꾼 경로를 10,000스텝 학습한다.
   추가 경로 4개는 2,000·5,000·10,000스텝에서 비교한다.

추가 파라미터 효과는 같은 구조·chunk·step의 기준 모델과 비교한다.
주 학습률 변경 시 ResNet 별도 학습률은 0.00001로 유지한다. 일반형/경량형은 폭·층 수를 함께
바꿔 모델 용량을 비교한 것이므로 폭 하나의 독립적 효과라고 표현하지 않는다.
스텝 비교는 한 연속 학습의 저장본이며, 각 스텝마다 독립 재초기화한 실험이 아니다.
학습률 스케줄러·워밍업·영상 증강·관절 노이즈는 사용하지 않는다.

## 학습·검증·평가 분리

- 학습: `[0,1,2,3,4,5,6,7,10,13,14]`, 11개 녹화·11,136프레임.
- 검증: `[8,12]`, 기본 시연 1개·보완 시연 1개.
- 별도 평가: `[9,11]`, 학습과 검증에서 제외.

0~10 기본·11~14 보완이라는 사용자 지정 역할은 유지한다. 각 역할에서 일부를 검증·평가에 남긴다.
15개를 전부 학습에 사용한 모델을 추가로 만들지 않는다. 이미 관찰했던 데이터이므로 새로 수집한
독립 현장 테스트라고 표현하지 않는다.

정규화 통계는 학습 녹화만으로 집계한다. 0.4.4에는 0.6.1의 `dataset.eval_split`이 없으므로
원본 train에 학습 ID만 전달하고, 저장본을 별도 검증기가 로드한다. 0.4.4 영상은 float 0~1로
반환되므로 다시 255로 나누지 않는다. 저장된 전처리·후처리기를 유지한다.

기준 지표는 앞 10개 미래 행동에 대한 녹화별 평균 관절 목표 MAE다. chunk 길이가 달라도 같은
10스텝으로 비교한다. 학습 표본 MAE·검증 MAE·기본/보완 녹화별 점수·gap을 함께 기록한다.
이 지표는 로봇 물체 배치 성공률이 아니다.

모든 비교 후 **검증 점수만으로 구조별 1개 후보**를 선택해 파일에 고정하고, 별도 평가를 수행한다.
선택 폴더 `selected/standard`, `selected/light`는 각각 실제 0.4.4 체크포인트 디렉터리를 가리킨다.

## 10만 스텝과 후속 후보

데이터 수만으로 10만 스텝이 반드시 과하다고 단정하지 않는다.
[공식 ACT 안내](https://huggingface.co/docs/lerobot/act)에도 100k 학습 예시가 있다.
이번 학습 표본 11,136개에서 배치 8×100,000은 관측 시작점을 약 71.8회 반복하는 근삿값이다.
인접 프레임과 행동 chunk의 중첩은 새 시연을 추가하지 않는다. 우선 20,000까지 학습·검증 추이를
확인한다. 학습 오차만 낮아지고 검증이 나빠지면 더 긴 학습을 성공으로 보지 않는다.

추가 후보로 dropout, 영상 증강, ResNet 별도 학습률, 배치 크기, KL 가중치, 반복 시드가 있다.
이번에는 주 학습률·감쇠만 추가 비교하고 나머지는 기능 설명과 향후 후보로 분리한다.

## 실행·결과·알림

```bash
scripts/mujoco/run_act044_training.sh
cat ~/omx_sim_runs/retraining_044_20261026/status.json
```

기존 실행 중인 첫 작업은 감독기가 PID를 인계해 기다린다. 동일 실행 폴더에 있는 완료 작업은
다시 실행하지 않는다. 원본 체크포인트의 resume 기능을 사용하고, 이미 고정한 계획이 달라지면
새 실행 폴더가 필요하다. 전체 상한은 최대 12시간이며 끝날 때 실제 완료·시간 제한·실패를 구분한다.

보고서는 [`lerobot044/report.html`](../../../docs/mujoco_validation/lerobot044/report.html)이다.
이전 0.6.1 결과와 파일을 섞지 않는다. 결과는 같은 MuJoCo 브랜치에 한국어 커밋으로 자동 푸시한다.
가중치는 Git에 넣지 않는다. 기존 디스코드 웹훅에는 30분마다 버전·완료 경로 수·검증 시점 수·현재
스텝·프로세스 상태를 전송하며, 종료 확인 뒤 마지막 상태를 보내고 정기 알림을 해제한다.

```bash
touch ~/omx_sim_runs/retraining_044_20261026/STOP  # 학습 감독기에 중단 요청
```

## 저장 모델의 실물 추론 실행기

바로 쓸 수 있는 경로는 `~/il_ws/run_act044.sh`다. Git 원본은
[`scripts/manipulation/run_act044.sh`](../../../scripts/manipulation/run_act044.sh)이며,
`~/venv/il/bin/python`과 로컬 0.4.4 소스만 사용한다. 0.6.1 모델을 자동 변환하지 않는다.

```bash
~/il_ws/run_act044.sh list                          # 모델 번호와 최신 저장 step
~/il_ws/run_act044.sh checkpoints 1                 # 1번 모델의 저장 단계 전체
~/il_ws/run_act044.sh check 1                       # CPU 모델 로딩만, 장치 연결 없음
~/il_ws/run_act044.sh run 1 --step 20000 --dry-run    # 명령만 표시, 장치 연결 없음

# 아래부터는 실제 모터를 움직인다.
~/il_ws/run_act044.sh run 1                         # 기본 10초 동작 점검
~/il_ws/run_act044.sh run 1 --step 20000 --duration 50
~/il_ws/run_act044.sh run 7 --duration 50            # 경량형 chunk16
~/il_ws/run_act044.sh run standard --duration 50     # 현재 일반형 검증 최저 후보
~/il_ws/run_act044.sh run light --duration 50        # 현재 경량형 검증 최저 후보
```

번호는 저장된 실험 계획의 1~12번으로 고정된다. 아직 학습 전인 모델은 저장본 대기로 표시한다.
저장 중인 파일을 피하기 위해 upstream의 완료된 `last` 표시와 전처리 파일을 확인한다.
`--step`을 생략하면 해당 실험의 현재 검증 최저 MAE 저장본, 검증 전이면 최신 완전 저장본을 고른다.
`--latest`는 검증 선택 대신 최신 저장본을 고른다. 전체 비교 종료 전의 후보는 최종 추천이 아닐 수 있다.

추론·하드웨어 설정은 오늘 생성한 `~/il_ws/act044_inference.env`에 모았다. 팔로워 포트·ID와
top/wrist 카메라 경로의 초깃값은 기존 로컬 설정에서 복사했다. 옛 번들의 `config.env`는 읽거나 수정하지 않는다.
`ACT044_INFERENCE_CONFIG`로 다른 추론 설정 파일, `--port`, `--top`, `--wrist`로 장치 경로를 지정할 수 있다.
초기 설정은 `--action-steps 5`, `--max-relative-target 3`, 30Hz다. 최대 이동량은 학습 데이터의
LeRobot 모터 위치 단위이며 도·라디안과 다르다. 학습 당시 초기 자세·카메라·물체 배치에서 실행한다.
실물 성공률은 아직 검증되지 않았다. 종료 시 0.4.4 드라이버가 토크를 해제하므로 팔을 지지할 준비가 필요하다.

0.4.4의 `lerobot-record --policy.path=...`로 추론하며 실행 기록은
`~/il_ws/outputs/act044_real_eval/`에 저장한다. `push_to_hub=false`로 외부 업로드는 하지 않는다.
실행 스크립트의 생성·구문 검사·원본 CLI 인자 파싱·CPU 모델 로딩·dry run만 확인했으며,
개발 과정에서 실제 로봇·카메라 연결 또는 모터 구동을 실행하지 않았다.
