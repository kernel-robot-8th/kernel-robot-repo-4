# 박스 외형·카메라 인식 정합 개선

기존 박스의 흰 면 위 빨간 구체는 실제 하트 인쇄와 다른 영상이었다. 뚜껑 두께·카메라 시점·과노출·강한 그림자도 실제 영상과 달랐다. 이번 수정은 같은 학습 가중치를 유지한 상태에서 이 차이를 줄이고, 박스 무늬 정합과 정책 반응·접촉을 각각 확인한다.

## 변경한 기본 환경

`config/scene.json`은 개선된 `scene_appearance_v2.json`과 같다. 기존 장면은 `scene_legacy.json`에 보존했다. 기존 실행의 `plan.json`과 결과는 수정하지 않았다.

| 조건 | 영상·카메라 | 박스 충돌·질량 |
|---|---|---|
| 기존 | 빨간 구체·기존 카메라·조명 | 원래 직육면체 18g |
| visual | 실제 두 종류의 뚜껑 인쇄, 카메라 모서리 정합, 과노출·그림자 감소 | **원래 충돌·18g 그대로** |
| v2 | visual과 동일 | 본체·뚜껑 65:35 질량, 뚜껑 1mm 돌출 포함, 전체 18g·높이·마찰 유지 |

상부 카메라는 녹화 0번·11번의 뚜껑 네 모서리, 손목 카메라는 0번 5초의 네 모서리로 맞췄다. 상부 수직 시야각 50도·손목 70도와 기존 크기를 가정한다. 평면 대응만으로 크기·깊이·카메라 위치의 실측을 인증하지 않는다. 작은 재투영 오차를 물리 보정 통과로 표현하지 않는다.

텍스처는 `Sungah/omx_1024_test_jihyeok_success`의 고정 리비전 `3502381b21fe15eae125dc36570779737ca85a71`에서 추출했다. 원본 라이선스·출처·주석·프레임 해시는 `config/textures/provenance.json`에 기록했다. 이미지에서 뚜껑을 투시 보정하고 MuJoCo XY 매핑에 맞춰 시계 방향 90도 회전했다. 실제 프레임을 가상 카메라 영상 대신 재생하지 않는다. 박스 위치·이동은 계속 MuJoCo 상태로 결정한다.

## 인식 확인의 의미

`print_detector.py`는 RGB의 SIFT·RANSAC과 분홍 뚜껑의 색상·형상 검사로 진단용 경계를 만든다. **검출 경계·시뮬레이터 정답 위치·주석을 ACT/CNN 입력에 넣지 않는다.** ACT/CNN은 표시 없는 렌더 영상과 관절값을 받는다.

녹화 0·2·11번의 0·5·10초 9개 관찰 사례에서 렌더의 무늬·색상 정합은 기존 0/9, 수정 후 8/9였다. 실제 영상 자체도 6/9에서만 검출됐고, 같은 무늬·보정 사진을 다시 보는 진단이다. 따라서 독립 검출 정확도나 모든 물체를 이해한다는 증거로 표현하지 않는다. 단색 흰색·분홍 배경을 박스로 오인하지 않는 검사를 추가했다.

최종 CNN·공식 ACT에 같은 실제 관절 상태를 주고 RGB만 실제/기존 렌더/수정 렌더로 바꿨다. 앞 10개 행동의 실제 영상 예측 대비 차이는 CNN 2.339→1.634로 줄었고, 공식 ACT 7.324→7.553으로 줄지 않았다. 가중치는 수정하지 않았다. 무늬 검출과 정책의 관측 분포 일치를 구분해야 한다.

## 실제 물리 비교

각 조건은 같은 체크포인트·장면 시드·50초·30Hz다. 학습 모델 66회·관절 유지 6회, 기록 명령 재생 6회를 사용한다. 새로 두 조건을 추가했으므로 추가 실행은 정책·대조군 144회와 재생 12회다.

세 조건의 모델 안정 배치는 각각 0/66, 기록 명령 재생도 각각 0/6이었다. 손가락 접촉 프레임 합계는 기존 96, visual 1,060, v2 878로 늘었다. 프레임이 길게 이어진 접촉을 독립 잡기 횟수로 세지 않는다. 들림·성공 지표·안전 제한을 완화하거나 박스를 그리퍼에 붙이는 변경은 하지 않았다.

**외형 정합은 개선됐지만 집기·배치 성공은 아직 재현하지 못했다.** 배경·로봇 표면·가림·카메라·그리퍼 접촉과 실측 치수의 검증이 남는다. 보고서는 [`appearance_report.html`](../../../docs/mujoco_validation/appearance_report.html)이다.

## 재현

저장소 루트에서 전용 가상환경과 원본 데이터·로봇 자산을 사용한다.

```bash
export PYTHONPATH="$PWD/src/cobot_mujoco"
export MUJOCO_GL=egl OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4
python_bin="$HOME/venv/omx_mujoco/bin/python"
"$python_bin" -m cobot_mujoco.appearance_fit \
  --source "$HOME/omx_sim_data/omx_1024_test_jihyeok_success" \
  --frames "$HOME/omx_sim_runs/appearance_20261025/frames" \
  --assets "$HOME/omx_sim_assets/robotis" --cache "$HOME/omx_sim_data/cache_v1" --activate

# 개선된 기본 환경의 비교 실행: 완료된 조건은 다시 실행하지 않는다.
scripts/mujoco/run_sim_comparison.sh
```

`appearance_probe` 모듈은 `--training`, `--frames`, `--assets`, `--cache`, `--output`으로 같은 진단을 재현한다. `appearance_report` 모듈은 `--training`, `--experiment`, `--destination`으로 두 조건과 기존 결과를 비교한 보고서를 생성한다. 저장된 계획과 설정이 다르면 별도 실행 이름을 사용해야 한다.

외형만 바꾼 조건이 원래 물리 궤적을 그대로 유지하는지 수치 비교하고, 분리한 뚜껑 충돌체의 총 질량과 성공 판정이 변조되지 않았는지도 검사한다.
