# 서비스 관리화면 사용법 (매장 직원용)

작성 2026-11-22. 매장 직원(운영자)이 주문을 보고 기본 조치를 하는 화면입니다.
개발·시험·진단은 [엔지니어 화면](screen_guide.md)(`/`)에서 합니다. API 형식은 [api.md](api.md#apiservice-서비스-화면) 를 봅니다.

## 여는 곳

- `http://<관제 PC 주소>:8080/service/` (실물 관제와 같은 백엔드 `fleet_api_node`, 포트 표 [docs/ports.md](../../../docs/ports.md))
- 엔지니어 화면 위쪽의 **서비스 화면** 링크, 서비스 화면 아래쪽의 **엔지니어 화면** 링크로 서로 오갑니다.
- 가짜 핑키(8181)·가제보(8182)·개발 읽기 전용(8180) 백엔드에서도 같은 주소로 열립니다. 실제 매장이 아니면 위쪽 칩이 주황 `시험 모드`, 읽기 전용이면 `보기 전용` 이고 조치 버튼이 꺼집니다.
- 로그인이 아직 없습니다. 같은 내부망의 누구나 열 수 있으니 손님 망에 내보내지 않습니다 ([매장 망 정리](../../../draft/store_network_overview.md) 는 개인 메모).

## 배치

```
┌ 매장 운영 · 실제 매장 │ ● 관제 ● 주문 처리기  12:34:56 │ [주문 처리 켜짐 · 끄기] [전체 비상정지] ┐
│ 조치 필요 띠 (멈춘 주문, 상차 확인, 정지 잠금, 로봇·로봇팔 경고. 빨강이 위)                     │
├─────────────────────────────────────────────┬────────────────────────────┤
│ 진행 중 주문 (카드)                           │ 로봇 (상태·배터리·맡은 주문) │
│   주문번호 · 접수 시각 · 경과                 │ 로봇팔 (상태)                │
│   상품 · 자리 · 로봇                          │ 재고 (남은 수량, 0 은 품절)   │
│   [접수][상품 준비][이동][전달][회수·정리][복귀] │                            │
│   지금 하는 일 · 조치 버튼                    │                            │
├─────────────────────────────────────────────┤                            │
│ 끝난 주문 (시각·결과·걸린 시간, 최근 30건)     │                            │
└─────────────────────────────────────────────┴────────────────────────────┘
```

좁은 화면(태블릿 세로·휴대폰)에서는 한 줄로 쌓입니다. 1초마다 새로 읽습니다.

## 단계

| 큰 단계 | 로봇이 하는 일 |
|---|---|
| 접수 | 로봇 배정을 기다림 |
| 상품 준비 | 상차장(ZB)으로 가서 로봇팔이 상품을 꺼내 실음 |
| 이동 | 고객 자리(또는 하차장)로 감 |
| 전달 | 고객이 신발을 꺼내 신어 보고 구매/구매 안 함을 고름 (최대 5분) |
| 회수·정리 | 고객이 사지 않았을 때만: 정리 구역(ZC)에서 정리 → 선반(ZA)에 되돌림. 아니면 줄 그어 흐리게 보임 |
| 복귀 | 대기 자리로 돌아감 |

지금 단계는 파랑, 멈춘 주문은 빨강입니다. 카드 아래 굵은 글이 지금 하는 일입니다 (예: `로봇팔이 상품 꺼내는 중`).

## 조치

모든 조치 판단은 주문 처리기(`fleet_control`)가 다시 검사합니다. 거절되면 아래쪽 알림에 그 이유가 나옵니다.

| 버튼 | 언제 보이나 | 하는 일 |
|---|---|---|
| **주문 처리 켜기 / 끄기** | 늘 | 꺼져 있으면 로봇이 주문을 받지 않습니다. 켤 때만 확인 창이 뜹니다 (`/api/commands/arm`, 엔지니어 화면의 '작업 명령 켜기'와 같은 스위치) |
| **전체 비상정지** | 늘 | 확인 없이 모든 로봇·로봇팔을 바로 세웁니다. 보내지 못하면 로봇의 비상정지 버튼을 직접 누릅니다 |
| **정지** (로봇) | 연결된 로봇 | 그 로봇만 세웁니다. 주문 중이면 주문이 멈춤이 되고 주문 카드에서 이어 가거나 취소합니다 |
| **정지 해제** (로봇) | 정지 잠금 | 현장 확인 체크 뒤 잠금을 풉니다 (`release_control`). 작업 구역 안에서 멈췄으면 해제 뒤 엔지니어 화면에서 '나가기'로 빼냅니다 |
| **상차 확인** (주문) | 상차장에서 멈춘 주문 | 로봇팔이 싣지 못했을 때 사람이 직접 싣고 세 가지를 체크하면 로봇이 출발합니다 (`confirm_loaded`) |
| **이어서 가기 / 주문 취소** (주문) | 멈춘 주문 | 이동 단계에서 멈췄으면 이어서 갈 수 있고, 아니면 취소만 됩니다. 취소는 로봇팔·상품·통로 정리 세 가지를 체크해야 합니다 (`recover`) |

- 확인 창에서는 필요한 칸을 모두 체크하고 **처리한 사람** 이름을 적어야 버튼이 켜집니다. 이름은 이 브라우저에 기억합니다 (엔지니어 화면과 같이 씀).
- 누가 눌렀는지는 적은 이름으로 fleet 기록에 남습니다. 정지 해제·주문 복구·주문 처리 켜기는 접속 IP 도 함께 남습니다.

## 하지 않는 것

- 재고 수정, 주문 만들기, 로봇 직접 조종, 웨이포인트, 로봇팔 켜기·끄기는 이 화면에 없습니다. 엔지니어 화면(`/`)을 씁니다.
- 끝난 주문은 fleet 주문 원장에 남아 있는 것만 보입니다. 관제를 다시 켜도 원장(SQLite)이 남아 있으면 그대로 보입니다.
- 지금은 `/` 가 엔지니어 화면입니다. 매장에서 직원이 쓰기 시작하면 `/` 를 서비스 화면으로 바꾸는 것을 검토합니다.
