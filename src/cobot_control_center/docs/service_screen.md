# 매장 관리화면 사용법

작성 2026-11-22. 매장 직원·관리자가 오늘 주문을 보고 기본 조치를 하는 대시보드입니다.
개발·시험·진단은 [엔지니어 화면](screen_guide.md)(`/`)에서 합니다. API 형식은 [api.md](api.md#apiservice-서비스-화면) 를 봅니다.

## 여는 곳

- `http://<관제 PC 주소>:8080/service/` (실물 관제와 같은 백엔드 `fleet_api_node`, 포트 표 [docs/ports.md](../../../docs/ports.md))
- 엔지니어 화면 위쪽의 **매장 관리화면** 링크, 관리화면 맨 아래의 **엔지니어 화면** 링크로 서로 오갑니다.
- 가짜 핑키(8181)·가제보(8182)·개발 읽기 전용(8180) 백엔드에서도 같은 주소로 열립니다. 실제 매장이 아니면 제목 옆에 주황 `시험 모드`, 읽기 전용이면 `보기 전용` 이 붙고 조치 버튼이 꺼집니다.
- 로그인이 아직 없습니다. 같은 내부망의 누구나 열 수 있으니 손님 망에 내보내지 않습니다 ([매장 망 정리](../../../draft/store_network_overview.md) 는 개인 메모).

## 배치

```
┌ [C] 매장 관리  11월 22일 일요일 · 14:05        ( ● 주문 받는 중 [멈추기] )  [비상정지] ┐
├ 오늘 주문 12 │ 진행 중 2 │ 판매 7 │ 회수 3 │ 실패 1                                     ┤
├ 할 일 (2) ──────────────────────────────────────────────────────────────────┤
│  ● 주문 A12 상차 확인 필요  pinky2 · SHOE42 · P22 자리            [확인하기]  │
│  ● pinky3 정지 잠금 (비상정지)                                    [정지 해제]  │
├ 주문 현황 ───────────────────────────────────────────────┬ 재고 ──────────┤
│ 접수 │ 상품 준비 │ 이동 │ 고객 응대 │ 회수·정리 │ 복귀    │ SHOE42   4개   │
│ [A13]│ [A12]    │      │ [A11]    │          │         │ ████████░░     │
├ 장비  ● 로봇 3/3 정상  ● 로봇팔 2/3 정상                          [자세히] ┤
├ 최근 주문 내역 (끝난 시각 · 주문 · 상품 · 자리 · 결과 · 걸린 시간)          ┤
└ ● 관제 ● 주문 처리기                                        엔지니어 화면 ┘
```

- 1초마다 새로 읽습니다. 화면이 좁으면(태블릿 세로·휴대폰) 한 줄로 쌓이고, 주문 현황은 주문이 있는 칸만 세로로 보입니다.
- 관제와 연결이 끊기면 위쪽에 빨간 띠가 뜨고 영업 상태가 `관제 연결 끊김` 이 됩니다.

### 영업 상태

| 표시 | 뜻 | 버튼 |
|---|---|---|
| ● 주문 받는 중 (초록, 깜빡임) | 로봇이 주문을 받아 움직입니다 | **멈추기**: 새 주문을 받지 않음. 바로 바뀝니다 |
| ● 주문 멈춤 (회색) | 주문이 들어와도 로봇이 움직이지 않습니다 | **주문 받기**: 확인 창 뒤 켭니다 |
| ● 주문 처리기 응답 없음 / 관제 연결 끊김 (빨강) | 주문 처리(`fleet_control`)나 관제가 꺼졌습니다 | 엔지니어에게 알립니다 |

엔지니어 화면의 '작업 명령 켜기/끄기'와 같은 스위치입니다 (`/api/commands/arm`).

### 오늘 숫자

관제 PC 시간으로 오늘 0시 뒤에 접수한 주문을 셉니다. **진행 중**만 날짜와 관계없이 지금 끝나지 않은 주문 수입니다.

| 타일 | 뜻 |
|---|---|
| 오늘 주문 | 오늘 접수한 주문 |
| 판매 | 고객이 구매한 주문 |
| 회수 | 고객이 사지 않았거나 5분 안에 고르지 않아 되가져간 주문 |
| 실패 | 처리하지 못한 주문 |

### 할 일

사람이 해야 하는 일만 모읍니다. 버튼이 있는 것이 위, 빨강이 먼저입니다. 없으면 `처리할 일이 없습니다` 가 보입니다.

| 할 일 | 버튼 |
|---|---|
| 주문 멈춤 (비상정지·결과 모름 등) | **처리하기** → 이어서 가기 / 주문 취소 (상차 확인도 기다리면 주문 상세 창) |
| 상차 확인 필요 | **확인하기** → 수동 상차 확인 |
| 주문에 문제 생김 (아직 진행 중) | **보기** → 주문 상세 |
| 로봇 정지 잠금 | **정지 해제** |
| 로봇 신발 실려 있음 (고객 5분 무응답 복귀) | **정지 해제**: 로봇 위 신발을 내린 뒤. 풀기 전에는 새 주문을 받지 않습니다. 재고는 저절로 돌아오지 않으니 엔지니어에게 수정을 요청 |
| 주문 처리기 응답 없음, 로봇 연결 끊김·배터리 부족·끼임, 로봇팔 알람 | 버튼 없음 (알림) |
| 상품 품절 | 버튼 없음. 선반을 채운 뒤 엔지니어에게 재고 수정을 요청 |

### 주문 현황

진행 중 주문을 큰 단계 칸에 놓습니다. 칩에는 주문번호, 경과 시간, 상품 → 자리, 지금 하는 일, 로봇이 있습니다.
주황 칩은 상차 확인 필요, 빨강 칩은 멈춘 주문입니다. 칩을 누르면 **주문 상세** 창이 뜹니다 (단계 막대, 상품·자리·로봇·접수 시각·경과, 문제, 가능한 조치).

| 칸 | 로봇이 하는 일 |
|---|---|
| 접수 | 로봇 배정을 기다림 |
| 상품 준비 | 상차장(ZB)으로 가서 로봇팔이 상품을 꺼내 실음 |
| 이동 | 고객 자리(또는 하차장)로 감 |
| 고객 응대 | 고객이 신발을 꺼내 신어 보고 구매/구매 안 함을 고름 (최대 5분) |
| 회수·정리 | 고객이 사지 않았을 때만: 정리 구역(ZC)에서 정리 → 선반(ZA)에 되돌림 |
| 복귀 | 대기 자리로 돌아감 |

### 재고

상품별 남은 수량과 막대입니다. 1개 이하는 주황, 0 은 빨강 `품절` 입니다. 고칠 수는 없습니다 (엔지니어 화면·fleet 설정).

### 장비

평소에는 한 줄 요약(`로봇 3/3 정상 · 로봇팔 2/3 정상`)만 보입니다. 로봇은 연결되고 정지 잠금이 없으면, 로봇팔은 `준비됨`·`작업 중` 이면 정상입니다.
**자세히**를 누르면 로봇(상태·배터리·맡은 주문, **이 로봇 정지** / **정지 해제**)과 로봇팔(상태·작업 중인 주문)이 펼쳐집니다. 펼침 여부는 이 브라우저에 기억합니다.

### 최근 주문 내역

끝난 주문 최근 30건입니다 (구매 완료 / 구매 안 함 / 고객 응답 없음 / 처리 못 함). 줄을 누르면 주문 상세 창이 뜹니다. 오늘이 아닌 주문은 시각 앞에 날짜가 붙습니다.

## 조치

모든 조치 판단은 주문 처리기(`fleet_control`)가 다시 검사합니다. 거절되면 아래쪽 알림에 그 이유가 나옵니다.

| 버튼 | 하는 일 |
|---|---|
| **비상정지** | 확인 없이 모든 로봇·로봇팔을 바로 세웁니다. 보내지 못하면 로봇의 비상정지 버튼을 직접 누릅니다. 뒤에 '할 일'에서 로봇마다 정지 해제 |
| **이 로봇 정지** | 그 로봇만 세웁니다. 주문 중이면 주문이 멈춤이 되고 '할 일'에서 이어 가거나 취소합니다 |
| **정지 해제** | 현장 확인 체크 뒤 잠금을 풉니다 (`release_control`). 작업 구역 안에서 멈췄으면 엔지니어에게 '나가기'를 요청합니다 |
| **상차 확인** | 로봇팔이 싣지 못했을 때 사람이 직접 싣고 세 가지를 체크하면 로봇이 출발합니다 (`confirm_loaded`) |
| **이어서 가기 / 주문 취소** | 이동 단계에서 멈췄으면 이어서 갈 수 있고, 아니면 취소만 됩니다. 취소는 로봇팔·상품·통로 정리 세 가지를 체크해야 합니다 (`recover`) |

- 확인 창에서는 필요한 칸을 모두 체크하고 **처리한 사람** 이름을 적어야 버튼이 켜집니다. 이름은 이 브라우저에 기억합니다 (엔지니어 화면과 같이 씀).
- 누가 눌렀는지는 적은 이름으로 fleet 기록에 남습니다. 정지 해제·주문 복구·주문 받기는 접속 IP 도 함께 남습니다.

## 하지 않는 것

- 재고 수정, 주문 만들기, 로봇 직접 조종, 웨이포인트, 로봇팔 켜기·끄기는 이 화면에 없습니다. 엔지니어 화면(`/`)을 씁니다.
- 매출 금액은 아직 없습니다. 상품 가격이 고객 화면(`cobot_gui`) 카탈로그에만 있어서입니다.
- 끝난 주문과 오늘 숫자는 fleet 주문 원장에 남아 있는 것만 셉니다. 관제를 다시 켜도 원장(SQLite)이 남아 있으면 그대로입니다.
- 지금은 `/` 가 엔지니어 화면입니다. 매장에서 직원이 쓰기 시작하면 `/` 를 관리화면으로 바꾸는 것을 검토합니다.
