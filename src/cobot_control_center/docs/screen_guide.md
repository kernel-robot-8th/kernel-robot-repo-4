# 관제 엔지니어링 콘솔 사용법

이 화면은 **엔지니어 전용**(개발·시험·진단) 화면입니다. 상단 제목 `관제 엔지니어링 콘솔`과 `엔지니어 전용` 표시로 구분합니다.
기능별로 시험하는 곳이고, 운영자가 주문을 다루는 서비스용 화면은 나중에 따로 만듭니다.

화면을 여는 방법은 [README 화면 보기](../README.md#화면-보기), API·데이터 형식은 [api.md](api.md) 를 봅니다.

## 배치

```
┌ 상단 바: 도메인·모드 칩 · 백엔드·관제 노드·작업 노드 점 [작업 명령 켜기] · zone_manager·브릿지 점 · [네트워크 상태보기] · [전체 비상정지] ┐
│ 경고 띠 (핑키 경고 + 로봇팔 활성 알람 + 네트워크·PC 경고, 있을 때만)                              │
├──────────────────────────────┬──────────────────────────────────────────────┤
│ 지도                          │ 로봇 카드 (폭에 따라 1~3장 나란히)            │
│ 범례 (체크박스별 한 줄)        │ 로봇팔 카드 (omx_1~3)                          │
│                              │ 작업 목록                                      │
│ 이벤트 로그 (로봇·팔)          │ 위험구역 A/B/C                                 │
│                              │ 개발: 수동 명령 (켜져 있을 때만)               │
└──────────────────────────────┴──────────────────────────────────────────────┘
```

좁은 화면에서는 한 줄로 쌓입니다.

화면의 시각은 모두 24시간 `HH:MM:SS` 입니다 (상단 갱신 시각, 이벤트 로그, 작업 목록, 수동 명령 로그).

## 상단 바

**백엔드**(WebSocket)·**관제 노드**(`fleet_status` 수신)·**작업 노드**(`fleet_control_node`) 점이 빨강이면 해당 연결이 끊긴 것입니다.
작업 노드 옆 **작업 명령 켜기 / 끄기** 버튼으로 작업 명령을 켜고 끕니다 ([작업 명령 켜기·끄기](#작업-명령-켜기끄기)).
제목 옆 칩은 지금 보는 도메인과 모드입니다. `도메인 100 · 실물` 이 아니면(가짜 핑키, 시험) 주황으로 표시합니다.
칩 끝에 `개발(읽기 전용)` 이 붙고 테두리가 점선이면 개발용 백엔드(8083) 화면입니다. 실물 데이터는 똑같이 보이지만 명령 버튼(정지 포함)은 모두 꺼져 있습니다. 명령은 실물 관제 화면(8080)에서 보냅니다.
그 옆 **zone_manager**·**브릿지 1 2 3** 점은 관제 PC 기반 노드 상태입니다 (마우스를 올리면 설명).

| 점 | 뜻 |
|---|---|
| 초록 | 정상 (하나 떠 있음) |
| 빨강 | 없음, 또는 **중복**(같은 도메인에 두 벌. zone_manager 가 둘이면 구역 판단이 갈라짐) |
| 주황 | 확인 불가. 위치를 내는 노드는 있지만 DDS 구현이 달라(예: Cyclone ↔ Fast DDS) 이름이 안 보임 |
| 회색 | 해당 없음(실물 도메인이 아님) 또는 관제 노드 끊김 |

경고가 있으면 상단 바 아래에 띠로 보입니다 (주황 주의, 빨강 위험). 배터리 부족, 연결 끊김, FAILED/STOPPED,
이동 중인데 오래 제자리(끼임 의심), 구역을 오래 점유한 경우입니다. 관제 노드가 끊기면 띠를 숨깁니다.
로봇팔 활성 알람(연결 끊김·비상정지·정지 유지·팔 자세 확인)도 같은 띠에 `omx_1 (ZA)` 처럼 나옵니다. 빨강이 위입니다.

네트워크·PC 문제도 같은 띠에 나옵니다 (네트워크 화면을 열지 않아도). 로봇 핑 끊김·느림, Station PC 의 모든 점검
(핑, 팔 노드, 보고 끊김, DDS·도메인 다름, CPU·온도 등), 관제 PC 의 로봇망 연결·DDS·CPU·온도 등입니다.
이 경고는 관제 노드와 따로 와서 관제 노드가 끊겨도 남습니다. 생길 때와 풀릴 때(`… 회복`)는 이벤트 로그에도 남습니다.

## 지도

위험구역을 겹쳐 그립니다. 주행 설정 파일(`pinkyN.yaml`, `zone_params.yaml`)을 읽기만 합니다.

| 표시 | 뜻 |
|---|---|
| 큰 원 + `A` | 구역 지점(`ZA` 등). 초록 비어 있음, 주황 점유, 회색 상태 모름. 원 크기는 표시용이며 실제 구역 넓이가 아님 |
| 빨간 × `A 출구` | `ZA_EXIT`. 구역을 나와 토큰을 반납하는 지점 |
| 빈 원 `A0`, `A1` .. | 대기 슬롯 (`A0` 이 맨 앞). 같은 자리의 슬롯은 `A0·B0` 처럼 합쳐 표시 |
| 마름모 `I1` .. | 로봇 홈 |
| 파란 점 + 선 `P1` .. | 일반 웨이포인트. 선은 도착 방향(yaw). 같은 자리는 `P1·P10` 처럼 합쳐 표시. `(0, 0, 0)` 인 P 지점은 미실측 예비값이라 숨기고 범례에 개수만 표시 |
| 로봇 색 알약 | 로봇 이름표 |

- 범례의 **구역 표시**(구역·출구·대기 슬롯·홈)와 **웨이포인트**(P) 체크박스로 따로 끄고 켭니다 (선택은 브라우저에 기억). 지점을 고르는 동안에는 꺼 둔 표시도 잠시 켜집니다.
- 지도에서 **로봇을 누르면** 그 로봇 카드로 스크롤하고 잠깐 강조합니다.
- 로봇마다 구역 좌표가 다르면 `fleet_api_node` 가 시작할 때 경고를 남깁니다.

## 이벤트 로그

핑키(state 변화, 연결·끊김, 구역 점유·해제, 경고 발생·해제)와 로봇팔([로봇팔 알람](#로봇팔-알람) 기록)을 한 타임라인에 시각 순(최신이 위)으로 보여 줍니다.
관제가 낸 **명령**도 남습니다: 주행 명령(`명령 zone:ZA` → `명령 완료 zone:ZA (12.3 s)`), 주문 단계(`주문 cust-… MOVE_PICKUP → PICK`, 배정 전 주문은 누구 칸이 `주문`), 주문이 팔에 보낸 작업(`주문 작업 PICK pick 요청` → 결과).
오른쪽 위 **보기**로 거릅니다: 전체 / 로봇 전체 / 로봇팔 전체 / 구역 / 명령·주문 / 로봇 하나 / 팔 하나. **명령·주문**은 주행 명령·주문 단계·팔 작업만 모아 "명령 → 결과" 순서를 보기 좋게 합니다.
백엔드 메모리에 최근 `events_max`(핑키)·`arm_events_max`(팔) 개만 두므로 백엔드를 다시 켜면 지워집니다.

## 로봇 카드

```
● pinky1  ▭ 91%                         연결    ← 이름 · 배터리 · 연결 배지
( 이동 중 )  MOVING  P3 · #0                     ← 상태 배지 · 원래 코드 · 설명
(0.30, 0.40) m · 90° · 수신 방금                ← 위치 · 마지막 수신
                      [위치 복사] [초기위치]     ← 위치 도구 (로봇을 움직이지 않음)
─────────────────────────────────────────────
🕹 명령 잠김: 로봇 작업 중 (MOVING)              ← 명령 바닥판: 명령을 보낼 수 있는지
[ 이동 ] [ 구역 ] [ 나가기 ] [ 홈 ] [ 경로 ]
[      정지      ] [     비상정지     ]
```

| 줄 | 뜻 |
|---|---|
| 배터리 | 30 % 이하 주황, 15 % 이하 빨강, 모르면 회색 `—` |
| 연결 배지 | `연결` / `끊김`(8초 이상 수신 없음) / `미수신`(켠 뒤 한 번도 못 받음) |
| 상태 배지 | 순찰 상태를 한글로. 색: 파랑 이동, 주황 대기, 초록 도착·완료, 빨강 실패·정지됨, 회색 유휴. 옆 작은 글이 원래 코드(MOVING 등)로, 이벤트 로그와 맞춰 볼 때 씀 |
| 상태 설명 | 순찰 노드 `detail` 그대로. `IDLE_WAIT 40` 은 유휴 복귀까지 설정된 시간 [s](카운트다운 아님), `#0` 은 경로 안에서 몇 번째 지점인지(0부터) |
| 위치 | x, y [m], yaw [°]와 마지막 수신 시간 |

길어진 글은 잘리고(…) 마우스를 올리면 전체가 보입니다.

### 위치 복사 (웨이포인트 실측)

로봇을 원하는 자리에 세운 뒤 **위치 복사**를 누르면 지금 위치 `[0.123, -0.456, 1.57]` (x, y [m], yaw [rad]) 가 클립보드에 들어갑니다.
`pinkyN.yaml` 의 `points` 값 형식과 같으므로 `P36: ` 뒤에 붙여 넣으면 됩니다. 서버에 저장하거나 로봇에 보내지 않고, 파일도 고치지 않습니다.
클립보드를 못 쓰는 환경이면 그 줄을 카드에 띄워 선택해 두므로 Ctrl+C 로 복사합니다.

다음이면 버튼에 `주의:` 가 뜹니다 (복사는 막지 않음): 이동 중, 연결 끊김, 위치를 받은 적 없음,
amcl 표준편차가 `teach_max_std_xy`·`teach_max_std_yaw` 초과.
amcl 은 로봇이 멈춰 있으면 위치를 새로 내지 않으므로 마지막 추정값을 씁니다.

### 웨이포인트 저장·관리 (2026-11-18)

상세 화면 조종 칸의 **웨이포인트 기록 시작**을 누르면 기록 카드가 열립니다.

1. 카드 맨 위 이름 칸이 만들 묶음 이름입니다 (기본 `pinky1 11-18 21:05`, 고쳐도 됨).
2. 로봇을 몰고 가서 **여기 추가 (R)** 를 누를 때마다 지금 위치가 `W1, W2 …` 로 저장되고 카드 목록과 오른쪽 확대 지도에 **1 → 2 → 3** 순번·점선으로 쌓입니다. 움직이는 중이면 먼저 세우고 1.2초 기다린 뒤 저장하며, 조종은 이어집니다. R 키는 기록 중이면 조종하지 않을 때도 먹습니다.
3. 목록의 **×** 는 그 지점을 빼고 지웁니다.
4. **완료**: 목록 순서대로 묶음 하나가 생깁니다 (같은 이름이 있으면 바꿀지 묻습니다). 경로 띠의 **묶음 불러오기**로 보냅니다.
5. **취소**: 이번 기록에서 추가한 지점을 모두 지웁니다 (확인 창).

한 번에 한 로봇만 기록합니다. 새로 고침해도 같은 탭이면 기록이 이어집니다. 저장한 점(**주황 빈 마름모**)은 묶음에 안 든 것은 늘 보이고, **묶음에 든 점은 묶음 보기로 그 묶음을 골랐을 때만** 보입니다 (다른 묶음 점이 쌓여 보이지 않게). 이동·경로를 고를 때는 모두 보입니다.

- **이동·경로에서 P 처럼 고를 수 있습니다.** 관제가 좌표를 명령에 실어 보내서, 로봇 설정 파일(`pinkyN.yaml`)을 고치거나 순찰 노드를 다시 켤 필요가 없습니다. `goto:P3,W1` 처럼 P 와 섞어도 됩니다.
- **구역 근처 주의**: 좌표 이동은 구역 토큰을 받지 않습니다. 구역 지점·출구 바로 옆에 저장해 두고 보내면 다른 로봇이 그 구역을 쓰는 중이어도 들어갈 수 있으니, 구역 근처에는 저장하지 마세요. 거리 검사(`zone_keepout_m`)는 기록이 너무 자주 막혀 **기본으로 꺼 두었습니다** (2026-11-18). 켜려면 관제 `config/fleet_api_node.yaml` 과 작업 노드 `PointRules` 에 같은 값을 넣습니다.
- 상단 바 **웨이포인트**(`#/waypoints`): 이름 바꾸기(이름을 누름, 묶음 안 이름도 함께 바뀜)·메모·지우기, **내보내기**(체크한 것 또는 전체를 `  W1: [x, y, yaw]` 줄로, 로봇 설정에 옮겨 적고 싶을 때).
- **묶음 보기**: 전체 화면 지도와 상세 화면 지도 머리의 **묶음 보기** 에서 묶음 하나를 고르면 그 순서가 분홍 1 → 2 → 3 순번·점선으로 그려집니다 (두 지도 함께, 고른 것은 브라우저에 기억).
- **묶음**: 지점 순서에 이름을 붙여 둡니다 (P·구역 지점·홈·관제 웨이포인트를 섞음). 경로 띠의 **묶음 불러오기**로 한 번에 채웁니다. 그 로봇이 갈 수 없는 지점(다른 로봇의 홈 등)은 빼고 띠에 알립니다.
- 이름은 로봇 설정에 이미 있는 이름(P1, ZA, I1 …)과 겹치면 안 됩니다. 저장 때 이동 중·위치 불확실성 큼·**벽에 가까움**(지도 벽에서 `wall_warn_m` 0.15 m 안, Nav2 가 길을 못 만들 수 있음)이면 **주의**로 남습니다 (저장은 됨).
- 파일: `~/.ros/cobot_control_center/waypoints_<site>_d<ROS_DOMAIN_ID>.json` (`waypoints_file` 로 바꿈). 도메인을 이름에 넣어 가짜 핑키·시뮬에서 저장한 점이 실물 파일에 섞이지 않습니다. **도커 web 컨테이너는 볼륨이 없어 컨테이너를 다시 만들면 지워집니다** (볼륨 경로로 `waypoints_file` 을 바꿔야 함).
- 로봇 쪽은 순찰 노드가 봉투의 `poses` 를 받는 버전이어야 합니다. 예전 순찰 노드는 `unknown point` 로 거절합니다 (엉뚱한 곳으로 가지 않음).

## 명령 보내기

명령은 작업 노드 `fleet_control_node` 가 켜져 있고 **작업 명령**이 켜져 있어야 보낼 수 있습니다 ([README 명령 켜기](../README.md#명령-켜기)). 실물 도메인이면 실물 로봇이 움직입니다.

### 작업 명령 켜기·끄기

버튼 글은 **누르면 할 일**이고, 색이 지금 상태입니다.

| 버튼 | 지금 상태 | 누르면 |
|---|---|---|
| `작업 명령 켜기` (회색 테두리) | 꺼짐: 이동·구역·나가기·홈과 수동 명령이 막힘 | 확인 창 `실물 로봇이 움직입니다 (도메인 100)` → 켜짐 |
| `작업 명령 끄기` (주황) | 켜짐: 작업 명령을 보낼 수 있음 | 확인 없이 바로 꺼짐 |

- 작업 노드는 bringup 과 함께 켜지지만 **작업 명령 꺼짐**으로 시작합니다. 작업 노드가 재시작해도 다시 꺼집니다. 시험이 끝나면 꺼 둡니다.
- 정지·비상정지·전체 비상정지·결과 모름 해제는 꺼져 있어도 됩니다.
- 켜기·끄기는 작업 노드 기록(`operator_arm`)에 누른 PC 의 IP 와 함께 남습니다.

### 명령 바닥판

카드의 첫 줄(조이스틱 아이콘)이 지금 명령을 보낼 수 있는지 알려 줍니다.

| 표시 | 색 | 뜻 |
|---|---|---|
| `명령 가능` · `명령 가능 · A 보유 중` | 초록 | 보낼 수 있음 (잡고 있는 구역이 있으면 함께 표시) |
| `작업 중: goto:P3,P7 · 진행 · P3` | 파랑 | 관제가 보낸 작업이 진행 중 |
| `결과 모름: zone:ZA · 눌러서 현장 확인 후 해제` | 빨강 | 결과를 모르는 작업이 있어 해제 전까지 새 명령 막힘. 누르면 해제 확인이 열림 |
| `명령 잠김: 상단 '작업 명령 켜기'를 누르세요` | 주황 | 작업 명령이 꺼져 있음 ([작업 명령 켜기·끄기](#작업-명령-켜기끄기)) |
| `명령 잠김: 로봇 작업 중 (MOVING)` 등 | 주황 | 작업 노드 꺼짐, 연결 끊김, 로봇이 스스로 움직이는 중(유휴 복귀 등) |

명령을 보낸 직후 잠깐 이 줄에 결과가 나옵니다 (`보냄: goto:P3 (t-…)` 초록, `이동 거절 (409): …` 빨강).

누를 수 있는 버튼은 파란 글자, 잠긴 버튼은 흐린 회색입니다. **나가기**는 잡은 구역이 없으면 꺼집니다 (구역 상태를 모르면 막지 않음). 구역을 잡고 있어도 **이동**·**구역**은 켜져 있고, 보내면 로봇이 먼저 구역을 나간 뒤 갑니다. 이동을 끝내고 홈 복귀를 기다리는 동안에도 다음 명령을 보낼 수 있습니다 (2026-11-09).

### 이동 · 구역 · 나가기 · 홈

누르면 그 카드 위에 **지점 고르기**가 덮입니다 (아래 정지 줄은 가리지 않음).

- 이동: 지도에서 P 점을 차례로 누르거나 이름 버튼으로 골라 경로를 만듭니다. 고른 지점에 순번(1, 2 ..)이 붙고, 지도에 로봇 위치부터 경로를 미리 그립니다.
- 구역: 구역 지점 하나를 고릅니다. 홈·나가기는 고를 지점 없이 확인만 합니다.
- 고른 경로(`P3 → P7`)를 확인하고 **보내기**. 취소는 **취소** 또는 Esc. 실물 도메인이면 경고가 뜹니다.
- 지점 목록(`/api/map/layers`)이 없으면 이름을 직접 적습니다 (`P1, P2`).

### 경로 (여러 지점 섞어 연결 주행, 2026-11-18)

**경로**는 일반 지점(P), 구역 지점(`ZA` 등), 자기 홈을 섞어 순서대로 고릅니다 (예: `P1 → P2 → ZA → P3 → I1`). 같은 지점을 여러 번 골라도 됩니다.

- 지점은 **지도에서** 누릅니다. 띠에는 이름 버튼 대신 고른 순서대로 칩(`P1 × → ZA × → P3 ×`)이 붙습니다. 칩의 `×`는 그 지점만, **되돌리기**는 마지막 지점 하나, **지우기**는 전부 뺍니다.
- 띠 머리(`3곳`)에 마우스를 올리면 백엔드가 나눌 구간을 미리 봅니다.

- 순찰 노드는 한 번에 명령 하나만 받기 때문에, 관제 백엔드가 경로를 구간으로 나눕니다. 이어지는 P·홈은 **이동** 하나로 묶고, 구역 지점은 하나씩 **구역**으로 보냅니다. 위 예는 `goto:P1,P2 → zone:ZA → goto:P3,I1` 세 구간이 됩니다.
- 앞 구간이 성공해야 다음 구간을 보냅니다. 구역 다음 구간을 받으면 로봇이 먼저 구역을 나갑니다.
- 진행 중에는 카드 상태 줄에 `경로 2/3 · zone:ZA · 진행`이 보이고, 다른 명령 버튼은 잠깁니다 (구간 사이에도 다른 명령이 끼지 않게).
- 한 구간이라도 실패·거절·결과 모름이면 거기서 멈추고 남은 구간은 보내지 않습니다. **정지**·**비상정지**·전체 비상정지를 누르면 남은 구간도 버립니다.
- 이벤트 로그(전체 화면 **명령·주문** 보기, 상세 화면 타임라인 '경로')에 `경로 시작 (3구간): 이동 P1 → 구역 ZA → 이동 P3`, `경로 1/3 성공: …`, `경로 완료` / `경로 취소 (2/3): 운영자 정지`(주황) / `경로 중단 (2/3): …`(빨강)이 남습니다.
- 작업 목록에는 구간마다 한 줄씩 나오고, 줄에 `경로 2/3` 꼬리표가 붙습니다 (구간 작업 ID 가 `<route_id>-<구간 번호>`). 백엔드를 다시 켜기 전 경로는 구간 수를 몰라 `경로 2` 로만 나옵니다.
- 진행은 브라우저가 아니라 백엔드(`fleet_api_node`)가 하므로, 창을 닫아도 경로는 계속 갑니다. 백엔드를 다시 켜면 남은 구간은 잊습니다 (그때 가던 구간만 끝까지 감).

### 초기위치

- 자리: 카드는 좌표 밑 `[위치 복사]` 옆, 상세 화면은 **위치** 칸의 `초기위치 [홈] [좌표 지정]`. 로봇을 움직이는 **홈** 명령과 헷갈리지 않게 명령 줄에서 뗐습니다 (2026-11-11).
- 로봇을 홈(I1~I3)에 놓고 켠 뒤, 지도에서 로봇이 홈에 안 보이면 누릅니다. 확인 창에 홈 이름과 좌표가 나옵니다.
- 확인하면 작업 노드가 그 로봇의 AMCL 위치를 홈으로 다시 잡습니다. **로봇은 움직이지 않습니다.**
- 작업 명령 켜기 없이, 정지 잠금 중에도 누를 수 있습니다. 작업 중이거나 로봇이 움직이는 중이면 꺼져 있습니다.
- 누른 뒤 지도에서 로봇이 홈 자리에 왔는지 봅니다. 홈이 아닌 곳에서 누르면 위치가 틀어지니, 로봇이 정말 홈에 있을 때만 씁니다.

#### 좌표 지정 (상세 화면)

로봇이 홈이 아닌 곳에서 위치를 잃었을 때 RViz `2D Pose Estimate` 대신 씁니다.

1. 상세 화면 **위치** 칸의 `[좌표 지정]` 을 누르면 상태줄 아래에 띠가 뜹니다. 처음 값은 지금 추정 위치입니다.
2. 확대 지도에서 로봇이 실제로 있는 곳을 **누르고, 누른 채 로봇이 보는 쪽으로 끕니다** (점선 원 + 화살표). 그냥 클릭하면 방향은 그대로입니다. 띠의 x · y [m] · 방향 [°] 을 직접 고쳐도 됩니다.
3. **보내기** → 확인 창에서 확인. 취소는 **취소** 또는 Esc. 지도 밖 좌표면 보내기가 꺼지고, 서버도 400 으로 거절합니다.
4. 켜지는 조건은 [홈] 과 같습니다 (멈춰 있는 로봇만, 작업 명령 켜기 불필요).

### 정지 · 비상정지

- 카드 맨 아래 줄에 있고(정지 = 빨간 테두리, 비상정지 = 꽉 찬 빨강), **확인 창 없이 바로** 보냅니다. 작업 노드가 살아 있으면 언제나 누를 수 있습니다.
- 정지는 그 로봇만 멈추고 **잠그지 않습니다**. 바로 다음 명령을 보낼 수 있습니다. 구역 안이면 구역 밖으로 물러나 토큰을 풉니다. 그 로봇에 주문이 걸려 있으면 비상정지처럼 제자리에 서고 보류됩니다 (2026-11-09).
- 비상정지(`estop`)는 구역 토큰을 쥔 채 그 자리에 멈추고 **그 로봇만 보류됩니다** (다른 로봇과 작업 명령은 그대로). [제어권 복구](#제어권-복구-정지-잠금-해제) 뒤에 다시 명령을 받습니다. 상단 **전체 비상정지**만 작업 명령 전체를 끕니다.
- 상단 바 **전체 비상정지**는 로봇 지정 없는 `estop` 한 번으로 모든 로봇·팔을 세웁니다. 작업 노드가 꺼져 있으면 눌리지 않습니다.

### 로봇팔

로봇 카드 아래 **로봇팔** 칸에 팔 3대(omx_1~3)가 나옵니다. Station PC 의 팔 노드가 내는 상태를 보여 주고, 켜기·끄기·정지를 보냅니다.
카드 이름 옆에는 그 팔이 맡은 자리와 PC 가 나옵니다 (예: `ZA 상차 · 8-OMEN`, 정해지지 않았으면 `PC 미정`). 마우스를 올리면 보드 시리얼이 보입니다. 바꾸는 법은 [README 현장 팔 배치](../README.md#현장-팔-배치).
켜기·끄기·정지는 상단 **작업 명령 켜기**와 상관없습니다. 이 버튼들은 팔을 움직이지 않습니다.
**작업 시험**(아래)만 실제 팔을 움직이므로 작업 명령 켜기가 켜져 있어야 합니다. 주문의 팔 작업(집기·싣기)은 주문 흐름이 보냅니다.

| 배지 | 뜻 |
|---|---|
| 미연결 (회색, 카드 흐림) | 팔 노드 상태가 안 들어옴. Station PC 노드·도메인 확인 |
| 꺼짐 | 토크 꺼짐. 켜기만 됩니다 (실행기 줄에 막힌 이유가 있으면 켜기도 잠김) |
| 고장 (빨강) | 팔 실행기가 멈춤. 꺼짐처럼 보이다가 켜기를 누르면 팔 노드가 '지금 FAULT' 로 거절하고, 그때 고장으로 바뀝니다. **끄기**로 꺼짐에 되돌린 뒤 다시 켭니다 |
| 대기 (초록) | 켜짐, 작업을 받을 수 있음 |
| 작업·연결 중 (파랑) | 연결 중이거나 작업 중이거나 끄는 중 |
| 정지 (주황) | 정지 유지 중 |
| 비상정지 (빨강) | 잠김. 정지 해제로는 안 풀리고 끄기 → 켜기로만 풀림 |

- 카드 글 줄은 다섯입니다: **토크·퇴피·쉬는 자세**, 실행기, 알람 요약, 응답, 작업(작업 시험·주문 작업). 줄마다 한 줄 고정이라 세 카드 높이가 같고, 긴 글은 마우스를 올리면 전체가 보입니다.
- **퇴피**는 팔이 안전 자세로 옮겨 **잰** 결과가 안전일 때만 초록입니다. 안 잰 것은 주황 `미측정`.
- **쉬는 자세**: 지금 관절과 실행기 `rest_pose` 의 차이 (그리퍼 제외). `맞음`(초록)이면 끄기가 됩니다. `벗어남 x.x`(주황, 가장 큰 차이)이면 끄기가 거절되니 현장에서 팔을 내립니다. 마우스를 올리면 관절별 차이와 허용값(±3)이 보입니다. `미설정` 은 실행기에 쉬는 자세가 없어 끄기가 늘 거절되는 상태, `모름` 은 실행기가 안 떠 관절 값이 없는 상태, `—` 는 팔 노드가 실행기 정보를 아직 안 보낸 상태입니다.
- **실행기** 줄 (팔 노드 info):
  - 켤 수 있으면 작업별 모델과 버전 (`pick omx_pick_za@v1 · load omx_load_za@v1`). 마우스를 올리면 모델 경로, `init_pose`·성공 판단 유무, 백엔드·보드 탐지가 보입니다. 끈 뒤에는 `지난 실행 · …` 으로 마지막으로 켰을 때 모델을 보입니다.
  - 켤 수 없으면 그 이유 (`실행기 없음 (backend=none)`, `보드 없음 …`, `실행기 고장 …`) 가 주황·빨강으로 나오고 **켜기**가 잠깁니다.
  - 모델 번들 규칙은 `tool/omx-dashboard` 브랜치 `omx_fleet/README.md` "모델 번들 규격".
- **관절 값**은 토크에 마우스를 올리면 보입니다 (lerobot 값 -100..100, 단위 없음, 작업 중에는 갱신 안 됨).
- **epoch·seq**(팔 노드가 받아들인 세션·순번)는 상태 배지에 마우스를 올리면 보입니다. 정지 여부는 배지와 알람 줄이 보여 줍니다.
- **응답** 줄: 버튼을 누르면 몇 초 동안 그 결과(보냄·수락·거절)가 굵게 나오고, 그 뒤에는 팔 노드가 받은 마지막 명령과 결과가 나옵니다. 거절이면 빨간 글로 사유가 나옵니다.
- 버튼
  - **켜기**: 확인 창 뒤 보냄. 실제 팔이면 연결하면서 토크가 잠깐 꺼졌다 켜집니다. **쉬는 자세에서, 팔 옆에 사람이 있을 때만** 켭니다.
  - **끄기**: 확인 창 뒤 보냄. 쉬는 자세일 때만 토크를 끄고, 아니면 팔 노드가 거절합니다 (팔을 옮기지 않음). 고장 상태를 푸는 데도 씁니다 (꺼짐일 때는 잠김, 고장일 때만 열림). 작업 중에는 먼저 정지.
  - **정지 해제**: 확인 창 뒤 보냄. 팔이 바로 움직이지는 않습니다.
  - **정지**·**비상정지**: 확인 창 없이 바로. 응답을 기다리는 중에도 누를 수 있습니다. 둘 다 토크를 유지한 채 제자리에 멈추는 소프트웨어 정지입니다 (전원 차단 아님).
    - **정지** (주황, 명령 `hold`): 잠깐 멈춤. **정지 해제**로 바로 다시 씁니다.
    - **비상정지** (빨강, 명령 `soft_latch`): 멈추고 잠금. 정지 해제로는 안 풀리고 **끄기 → 켜기**를 거쳐야 합니다. 문제가 있어 처음부터 다시 켜게 할 때 씁니다.
- **작업 시험** (개발용): 선택 칸에서 작업(집기 pick·싣기 load·내리기 unload·창고 보관 warehouse_store·신발 정리 arrange_shoe)을 고르고 누르면, 확인 창 뒤 그 팔에 작업 한 건을 보냅니다.
  - **상자 번호**: 그 작업 모델이 상자 번호를 받으면(예: omx_1031 E 모델, 팔 노드 info 의 `box_required`) 작업 칸 옆에 `상자 —/1~4` 칸이 나옵니다. 위에서부터 셉니다 (1·2 = 맨 윗층 위·아래, 3 = 둘째 층, 4 = 셋째 층). 고르지 않으면 보낼 수 없습니다. 주문에서는 fleet_control 이 재고 칸의 선반 행(`shelf_row`)을 같은 값으로 보냅니다.
  - **실제 팔이 움직입니다.** 팔 옆에 사람이 있고 작업 자리에 물건이 있을 때만 씁니다.
  - 선택 칸에는 **그 자리 팔이 하는 작업만** 나옵니다 (`config/site_arms.yaml` 의 `actions`: ZA·ZB 집기·싣기, ZC 는 아직 없음 → `작업 없음`).
  - 상단 작업 명령 켜기가 켜져 있고, 팔이 **대기**이고, 앞 작업 시험이 끝났을 때만 눌립니다.
  - **주문이 진행 중이면 쓰지 않습니다.** 주문 작업과 같은 팔에서 부딪힙니다.
  - 카드의 **작업 시험** 줄에 진행 중(경과 시간) → 성공·실패·결과 없음과 걸린 시간, 사유가 나옵니다. 실패에 `팔 자세 확인 필요` 가 붙으면 작업 도중 멈춘 것이라 현장에서 팔 자세를 봅니다.
  - 주문이 그 팔에 작업을 보내면 같은 줄이 `주문 cust-… PICK 집기 (pick) 진행 중 · 경과` → 결과로 바뀝니다 (마우스를 올리면 request·핑키). 주문 작업이 진행 중이면 작업 시험 버튼이 잠깁니다.
  - 작업 중 멈추려면 **정지**를 누릅니다.
- 지금 상태에서 안 되는 버튼은 잠깁니다 (마우스를 올리면 이유). 최종 판정은 팔 노드가 하고, 결과는 응답 줄에 잠깐 나옵니다.
- 팔 노드가 8초 안에 답하지 않으면 `504` 로 알립니다. 팔 노드·도메인·**두 PC 시계**를 확인합니다 (명령 유효 기한 5초를 팔 쪽 시계로 봄).
- 급할 때 가장 빠른 것은 현장의 **팔 12 V 전원 차단**입니다 (팔이 떨어지니 받칠 것).

#### 로봇팔 알람

팔 알람은 따로 칸을 두지 않고, 핑키와 함께 봅니다 (보통 관제처럼 알람은 한 목록, 기록은 한 타임라인).

- **활성 알람**은 상단 **경고 띠**에 `omx_1 (ZA) 정지 유지 중: …` 처럼 핑키 경고와 같이 나오고, 풀리면 사라집니다. 팔 카드에도 `알람 2 · 정지 유지 중 · 팔 자세 확인` 요약 한 줄이 보입니다.
  - 연결 끊김 (빨강): 팔 상태가 안 들어옴. Station PC 팔 노드·네트워크 확인
  - 비상정지 잠김 (빨강): 끄기 → 켜기로만 풀림
  - 정지 유지 중 (주황): 정지 해제 또는 끄기
  - 팔 자세 확인 (빨강): 작업이 도중에 멈췄거나 결과가 없음. 현장에서 팔을 보고, 쉬는 자세면 끄기로 풀거나 다음 작업이 성공하면 풀림
- **기록**은 [이벤트 로그](#이벤트-로그)에 핑키 기록과 시각 순으로 섞여 나옵니다 (누구 칸에 `omx_1 ZA`). 연결·끊김, 상태 바뀜(정지 등), 팔 노드 다시 켜짐, 명령 응답(수락·거절, 다른 곳이 낸 명령 포함), 응답 없음, 작업 결과(작업 시험·주문 작업). 주황은 거절·팔 안 움직인 실패, 빨강은 끊김·도중 실패.
- 팔 기록은 백엔드 메모리에만 있어 관제를 다시 켜면 지워집니다 (300개까지).

### 위험구역 칸

구역마다 점유 로봇과 대기열(`대기 pinky2 → pinky3`, 앞 순번부터)을 보여 줍니다.

#### 구역 강제 해제 (2026-11-18)

로봇이 구역 토큰을 쥔 채 꺼지면 zone_manager 는 그 로봇이 나갔다고 알릴 때까지 점유를 풀지 않습니다 (시간이 지나도 그대로). 다시 켜진 로봇은 토큰을 잊어서 **나가기**를 `no zone held` 로 거절합니다. 그대로 두면 그 구역은 계속 점유로 보이고 대기 로봇은 계속 기다립니다. 경고 띠에는 빨간 `구역 A 점유 중인데 로봇은 토큰을 잊음` 이 뜹니다.

- 점유 칸에 빨간 **강제 해제** 버튼이 보이는 때: 점유 로봇이 (a) 연결 끊김, 또는 (b) 연결됐고 멈춰 있고 그 구역을 잡고 있지 않다고 보고할 때 (다시 켜져 잊음).
- 로봇이 살아 있고 아직 잡고 있다고 알면 버튼이 없습니다. **나가기**로 빼냅니다. 진행 중인 주문이 있으면 주문 복구를 먼저 합니다.
- 누르면 확인 창이 뜹니다. **현장에서 로봇이 구역 밖에 있는지 확인한 뒤** 확인을 누릅니다. 관제가 그 로봇 이름으로 `/zone_manager/notify_exit` 을 한 번 내고, 대기 중인 로봇이 바로 들어옵니다. 작업 명령 켜기는 필요 없습니다.
- **주의: 로봇이 실제로 구역 안에 있는데 풀면 다음 로봇이 들어와 부딪칠 수 있습니다.** 특히 (a) 연결만 끊긴 로봇은 관제가 위치를 모르므로 현장 확인이 유일한 안전장치입니다. 구역 안이면 손으로 꺼내거나 켠 뒤 같은 구역으로 **구역** 명령을 다시 보내 토큰을 되찾고 **나가기**를 씁니다.
- 누른 사람은 접속 PC(IP)로 기록됩니다 (작업 노드 기록 `zone_release`).
- 풀고 난 뒤 그 로봇이 순찰 노드를 다시 켜지 않은 채 연결되면 로봇은 아직 잡고 있다고 알 수 있습니다. 이때 주황 `로봇은 구역 A 를 잡았다고 아나 zone_manager 는 …` 경고가 뜹니다. 그 로봇의 나가기는 zone_manager 가 무시하므로 해롭지는 않지만, 현장을 확인합니다.

### 작업 목록

관제가 보낸 명령 기록입니다. 한 줄에 `시각 · 로봇 · 명령(이동 P3→P7) · 결과 · 이유/걸린 시간` 이고, 작업 번호·규격(v1/v2)·원래 명령은 마우스를 올리면 보입니다.

- **결과 모름**(빨강)·**진행 중**(파랑)은 맨 위에 고정됩니다.
- 제목 옆에 `진행 N · 결과 모름 N` 요약, 오른쪽에 로봇 필터가 있습니다. 최근 50개까지 봅니다.
- 로봇이 혼자 하는 순찰·유휴 복귀는 관제 명령이 아니라 여기 나오지 않습니다 (이벤트 로그에서 봄).

### 결과 모름 해제

결과 모름은 로봇이 실제로 움직이고 있을 수 있다는 뜻이라, 해제 전에는 그 로봇에 새 명령을 보내지 않습니다 (왜 생기는지는 [api.md 작업·주문](api.md#작업주문-fleet_control_node)).

1. 현장에서 로봇이 멈춘 것을 확인합니다.
2. 작업 줄의 **현장 확인 후 해제** 또는 카드의 빨간 결과 모름 줄을 누르면 확인 창이 한 번 뜹니다.
3. **확인**을 누르면 실패로 기록되고 다시 명령을 받습니다. 메모 입력은 없습니다 (2026-11-09).

그 로봇이 **정지 잠금(보류)** 중이면 해제 대신 **제어권 복구** 확인 창이 뜨고, 버튼 글도 **현장 확인 후 복구**로 바뀝니다. 해제(fleet `resolve`)는 로봇이 재부팅해 잠금이 풀린 채 올라오면 거절될 수 있어, 보류 중일 때는 복구 하나로 보류와 결과 모름을 같이 풉니다.

### 제어권 복구 (정지 잠금 해제)

카드 상태 줄이 빨간 **정지 잠금**이면 (비상정지·주문 중 정지 뒤, 또는 움직이던 중 하트비트 끊김·관제 재시작 뒤. 놀던 로봇은 끊김·재시작에 잠기지 않음) 그 줄을 누릅니다. "현장에서 로봇이 멈춰 있고 주변이 안전한지 확인했나요?" 확인 창이 뜨면 현장을 보고 **확인**을 누릅니다. 이름·메모 입력은 없고, 누가 눌렀는지는 접속 PC(IP)로 기록됩니다. 결과 모름 작업이 함께 있어도 복구 하나로 같이 풀립니다 (결과 모름은 실패로 기록). 전체 비상정지 뒤라면 작업 명령이 꺼져 있으니 상단에서 다시 켭니다. 구역 안에서 잠긴 경우도 복구할 수 있습니다. 복구한 뒤 **나가기**로 빼냅니다 (그때까지 다른 로봇은 그 구역에 못 들어옴).

### 멈춘 주문 복구

주문(배달) 중 로봇이 멈추면(비상정지·통신 끊김 등) 카드 상태 줄이 빨간 **주문 o1 멈춤 (비상정지) · 눌러서 이어서 가기/취소** 가 됩니다. 결과 모름·정지 잠금보다 먼저 뜨고, 주문 복구 하나로 보류와 하위 작업까지 함께 정리합니다.

1. 현장에서 로봇·상자·주변을 봅니다.
2. 줄을 누르면 확인 창이 뜹니다.
   - 이동 중(창고·카운터로 가는 중, 홈 복귀 중, 고객 수령 대기)에 멈췄으면 먼저 **"이어서 갈까요?"** → 확인이면 그 자리부터 다시 갑니다.
   - 거기서 취소를 누르거나, 팔 작업 중에 멈췄으면 **"주문을 취소할까요?"** → 확인이면 주문을 실패로 끝냅니다. 실은 상자는 사람이 꺼내고, 로봇은 제자리에 둡니다 (필요하면 **홈**을 따로 보냄).
3. 팔 작업은 자동으로 다시 하지 않습니다 (상차 단계는 아래 수동 상차 확인으로 이어 갈 수 있음).

지금은 임시 일반형입니다. 멈춘 단계별 확인 항목·취소 뒤 홈 복귀는 시나리오가 정해진 뒤 붙입니다.

### 수동 상차 확인

팔이 연결되지 않았거나 실패해서 주문이 상차장에서 멈추면, 그 로봇 카드 상태 줄이 빨간 **상차 확인 대기 · 주문 o1 (box_a) · 눌러서 현장 확인** 이 됩니다 (상차장 도착 뒤 상차 검증 단계의 주문만).

1. 현장에서 주문 상품(SKU)을 로봇에 직접 싣습니다. 로봇팔이 물러나 있고, 로봇 뒤 통로가 비어 있는지 봅니다.
2. 상태 줄을 누르면 **수동 상차 확인** 띠가 뜹니다. **현장 확인: 적재됨·팔 퇴피·통로 비움**을 체크하고 운영자 이름을 넣습니다 (이름은 이 브라우저에 기억됨). 메모는 기록에 남습니다.
3. **현장 확인함 · 상차 완료**를 누르면 fleet 이 상차장 도착·정지·통신·구역·예약을 검사하고, 통과하면 로봇이 **상차 구역 이탈부터** 이어서 갑니다. 거절되면 fleet 이 낸 이유가 상태 줄에 잠깐 보입니다. 취소는 Esc.

빨간 줄을 누르면 상차 확인 → 멈춘 주문 복구 → (보류 중이면) 제어권 복구 → 결과 모름 해제 → 정지 잠금 복구 순으로 맞는 것이 뜹니다 (fleet 이 상차 확인을 받으면 잠금도 풉니다).

## 네트워크 상태 화면

상단 바의 **네트워크 상태보기** 버튼을 누르면 네트워크 화면으로 바뀝니다 (주소 `#/network`, 북마크·새로 고침 가능).
**← 전체** 나 브라우저 뒤로 가기로 돌아갑니다. 버튼 옆 점은 네트워크 전체에서 가장 나쁜 상자 색입니다 (화면 밖에서도 2초마다 갱신).

평소에는 **5초마다 핑만** 보냅니다 (장치 5대, 초당 약 80 바이트). 제목 줄의 **자세히 확인 (10초)** 를 누르면
10초 동안 1초마다 핑하고, 로봇 `patrol_status`·팔 상태 토픽의 수신 주기(Hz)도 잽니다. 끝나면 버튼 옆에
"마지막 자세히 확인 HH:MM:SS" 가 남고 수신 주기는 그때 값을 그대로 보여 줍니다. 로봇에는 아무것도 보내지 않으므로
개발 화면(8083, 읽기 전용)에서도 누를 수 있습니다.

| 색 | 뜻 |
|---|---|
| 초록 | 정상 |
| 주황 | 주의: 핑이 느리거나(평균 100 ms 이상) 손실 10 % 이상, 브릿지 확인 불가, 팔 일부만 연결 |
| 빨강 | 끊김·이상 |
| 회색 | 모름 또는 해당 없음 (실물 도메인이 아니면 브릿지·zone_manager 는 회색) |

- **헬스체크** (맨 위): 윗줄은 장비(로봇 3대, 로봇팔 3대 omx_1~3), 아랫줄은 PC(Station PC, 관제 PC) 카드입니다. 위쪽 **지금 볼 것** 줄에 정상이 아닌 점검만
  나쁜 것부터 모입니다 (누르면 그 장치를 자세히). 오른쪽 위 숫자는 점검 개수(정상·주의·이상·모름)입니다.

  | 카드 | 점검 |
  |---|---|
  | 로봇 | 연결(마지막 수신), 네트워크(핑·손실), 배터리, 위치 추정(amcl 오차), 작업 상태(FAILED·끼임·정지 잠금), 시계 차이, 로봇 내부 |
  | 로봇팔 (팔마다) | 연결(마지막 수신), 상태(미연결·정지·정지 잠금), 전원(켜진 뒤에만), 상태 주기(자세히 확인 때) |
  | Station PC | 네트워크(핑), MAC(관제 PC ARP 표), 팔 노드(연결된 팔 수), 노드(도메인에서 보이는 `omx*_adapter` 이름. 팔 상태는 오는데 이름이 안 보이면 DDS 가 다를 수 있음). Station PC 에서 `host_status.launch.xml` 을 띄우면 보고 노드, DDS·도메인(관제와 다르면 주황), 연결(유선→무선→VPN), CPU·메모리·온도·디스크(기준 넘으면 주황)·켜진 시간이 더 나옴. 안 띄웠으면 회색 'PC 내부 · 보고 노드 없음' |
  | 관제 PC | 관제 노드(응답 없는 노드 이름), 브릿지, DDS(이름 안 보이는 노드), 연결을 **유선 → 무선 → VPN** 순서로 하나씩, CPU·메모리·온도·디스크·켜진 시간(`fleet_api.launch.xml` 이 함께 띄우는 `host_status_node host:=control`) |

  연결 줄은 보통 네트워크 설정 화면처럼 씁니다: 유선은 `연결됨 · IP · 1000 Mb/s`, 무선은 `연결됨 · IP · SSID · 신호 · 5 GHz ch44 · 전송 속도`.
  용도는 배지로 붙습니다: **[로봇망]**(공유기로 가는 연결), **[기본 경로]**(인터넷으로 나가는 기본 게이트웨이), **[VPN]**.
  판정은 [로봇망] 연결만 합니다. 나머지 연결은 끊겨도 회색입니다.
  팔 카드를 누르면 구조도의 Station PC 상자 내용이 자세히 칸에 나옵니다.

  로봇 판정은 상단 경고 띠와 같은 기준입니다 (배터리 20 % 이하, 시계 0.5 초 넘게 차이 등, `fleet_status_node.yaml`).
  **로봇 내부**(CPU·온도·로봇 Wi-Fi)는 로봇이 `/diagnostics` 로 보내 줘야 해서 지금은 회색 '미연결'입니다.
- **구조도**: 위 점선 상자가 관제 PC 입니다. 제목 줄에 도메인·DDS 종류(RMW), 로봇망 주소·연결(예: `Wi-Fi wlo1 · SK_D490_5G 77% · ch44`)·다른 연결 수·노드 수가 있고,
  안에 관제 노드(fleet_api, fleet_status, fleet_control, zone_manager, arm_command, net_status)와 로봇별 브릿지가 있습니다.
  그 아래 공유기, 맨 아래 Station PC(팔 3대, 관제와 같은 도메인·브릿지 없음)와 핑키 3대(브릿지 경유)입니다.
  선 색은 그 구간 핑 판정, 선 위 숫자는 마지막 핑 지연입니다.
- 장치 상자의 둘째 줄이 끊긴 곳을 알려 줍니다.
  - **네트워크 끊김 (핑 응답 없음)**: 와이파이·전원·공유기 쪽
  - **핑은 되는데 데이터 없음 (브릿지 확인 / 로봇 노드 확인)**: 장치는 살아 있고 ROS 쪽 문제
  - **핑은 되는데 팔 상태 없음 (팔 노드 확인)**: Station PC 는 살아 있고 팔 노드 쪽 문제
- 상자를 누르면 아래 **자세히** 칸에 내용이 나옵니다. 관제 PC 는 DDS 설정(`RMW_IMPLEMENTATION`, `CYCLONEDDS_URI`, 발견 범위)과
  도메인에서 보이는 노드 목록, **이름 안 보이는 노드** 수(발행은 보이는데 이름이 안 오면 DDS 구현이 다를 수 있음)와
  유선·무선·VPN 묶음별 연결(배지, 게이트웨이, MAC, 링크가 끊겼다 붙은 횟수, 무선은 같은 채널의 다른 AP)을 보여 줍니다.
  로봇·Station PC 의 DDS 종류는 ROS 로 물어볼 수 없어 데이터가 오는지로만 적습니다.
- **핑 지연** 그래프: 최근 5분. 점선은 주의 기준, 아래 빨간 눈금은 응답이 없던 순간입니다.
- 측정 노드(`net_status_node`)가 꺼져 있으면 핑 칸과 그래프가 비고, 나머지 상자는 기존 상태값으로 그립니다.
- 대역폭·WiFi·패킷 캡처 같은 자세한 진단은 `cobot_navigation/ros2_network_test` 를 따로 실행합니다.

## 로봇 상세 화면

로봇 카드 오른쪽 위의 **상세 ›** 버튼(또는 이름)을 누르면 그 로봇 한 대만 보는 화면으로 바뀝니다 (주소 `#/robot/pinky1`, 북마크·새로 고침 가능).
**← 전체** 또는 브라우저 뒤로 가기로 돌아갑니다. 상단 바와 경고 띠는 두 화면이 같이 씁니다.

```
┌ ← 전체  ● pinky1 [연결] (이동 중) 배터리 72%      명령 가능                       ┐
│                                              [이동][구역][나가기][홈][경로] [정지][비상정지] │  ← 스크롤해도 위에 붙음
├───────────────────────────────────┬────────────────────────────┤
│ 카메라 (크게)                       │ 지도: 이 로봇 중심 확대 [＋][－] │
│                                   │ 진행 중 경로 점선 · 다른 로봇 흐리게 │
├────────────┬────────────┬────────────┬────────────┤
│ 현재 작업    │ 위치        │ 구역        │ 최근 작업    │
├───────────────────────────────────┬────────────────────────────┤
│ 타임라인 (작업 + 상태 변화, 최신 위) │ 진단 (마지막 수신) · 추가 필드  │
└───────────────────────────────────┴────────────────────────────┘
```

| 칸 | 뜻 |
|---|---|
| 상태줄 | 연결·상태·배터리와 명령 버튼. 명령 버튼·잠김 이유·결과 메시지는 카드와 같습니다. 이동·구역·경로를 누르면 지점 고르기 띠가 상태줄 바로 아래에 열리고, 지점은 띠의 버튼이나 확대 지도를 눌러 고릅니다 |
| 카메라 | 로봇 카메라 영상 (`camera_topic_format` 토픽의 JPEG). 3초 넘게 새 프레임이 없으면 `영상 없음 · 마지막 수신 N초 전`, 받은 적이 없으면 `영상 없음 (아직 받은 적 없음)`. 다시 들어오면 저절로 다시 붙음 |
| 지도 | 기본은 지도 전체, ＋ 를 누르면 이 로봇을 가운데로 1.4 m · 0.8 m 확대. 진행 중 작업의 경로를 점선과 순번으로 그림. 다른 로봇을 누르면 그 로봇 상세로 |
| 요약 | 현재 작업(진행·결과 모름), 위치(x, y, yaw, 웨이포인트), 구역(점유·대기 순번), 최근 작업(받은 작업 목록 안의 성공·실패 수, 하루 전체 집계 아님) |
| 타임라인 | 이 로봇의 상태 변화 이벤트와 작업 결과를 시간순(최신 위)으로 합침. 최근 50줄 |
| 진단 | 연결·위치·배터리·순찰 상태·카메라의 마지막 수신 시간. 8초 안 초록, 30초 안 주황, 넘으면 빨강, 받은 적 없으면 회색 (실물 배터리는 5초 주기, 서 있는 로봇은 위치를 잘 안 냄). 명령 규격 v1/v2, 순찰 노드 추가 필드(`command_id` 등) |

- 카메라 칸 아래에 **직접 조종** 칸이 있습니다 (아래 절).
- 실물 카메라는 브릿지(`cobot_domain_bridge`)에 카메라 토픽이 들어가야 보입니다. 그 전에는 실물에서 늘 `영상 없음` 입니다.
- 없는 로봇 이름이면 `등록되지 않은 로봇입니다` 만 보입니다.

### 직접 조종 (2026-11-18)

카메라를 보면서 로봇을 조금씩 옮길 때 씁니다. **실제 로봇이 움직입니다.**

1. **조종 시작**을 누릅니다. 그 전에는 버튼·키보드가 로봇에 가지 않습니다 (실수로 키를 눌러 움직이지 않게).
2. ▲▼◀▶ 를 **누르고 있는 동안만** 움직입니다. 키보드는 `W A S D`·방향키, `Space` 멈춤, `Esc` 조종 끝.
3. **조종 끝**을 누르면 로봇을 세우고 놓습니다.
4. **웨이포인트 기록**: 아래 [웨이포인트 저장·관리](#웨이포인트-저장관리-2026-11-18) 절.

- 최대 속도는 `teleop_node` 설정 (`config/teleop_node.yaml`, 기본 0.15 m/s · 0.6 rad/s) 입니다. 칸 아래에 보입니다.
- **조종을 시작할 수 있는 때**: 연결됨, 작업 명령 켜짐, 정지 잠금 아님, 진행 중이거나 결과 모르는 작업·경로·주문 없음, 순찰 상태가 움직이는 상태(`MOVING` 등) 아님. 아니면 버튼이 꺼지고 이유가 보입니다. 순찰 노드·Nav2 와 `cmd_vel` 이 겹치지 않게 하려는 것입니다.
- **조종 중에는** 그 로봇의 이동·구역·경로·초기위치·수동 명령이 잠깁니다 (API 409). 정지·비상정지는 조종을 끝내고 그대로 나갑니다.
- **조종이 저절로 끝나는 때**: 화면 입력이 0.3초 끊김(창 닫힘·네트워크), 창이 포커스를 잃음·다른 탭, 다른 화면으로 이동, 로봇 연결 끊김, 작업·주문이 생김, 정지 잠금, 작업 명령 꺼짐. 끝날 때 0 속도를 5번 냅니다. 끝난 이유는 칸에 빨간 글로 남습니다.
- 한 로봇은 한 화면에서만 조종합니다. 다른 화면에서는 `다른 화면에서 조종 중` 으로 막힙니다.
- **한계**: 관제 PC 와 로봇 사이(브릿지·와이파이)가 끊기거나 `teleop_node` 가 죽으면 로봇에 마지막 속도가 남을 수 있습니다. 로봇 쪽 `cmd_vel` 타임아웃은 주행 담당 확인이 필요합니다. 로봇 근처에서 지켜보며 씁니다.
- 경로: 브라우저 → `WS /ws/teleop/<robot>` (`fleet_api_node`) → `/control_center/teleop_cmd` → `teleop_node` → `/pinkyN/cmd_vel` → 브릿지 → 로봇 `/cmd_vel`.

## 개발용 수동 명령

순찰 노드에 문자열을 그대로 보내 보는 칸입니다. 오른쪽 칸 맨 아래 **"개발: 수동 명령"** 을 펼쳐 로봇을 고르고 `goto:P3,P7`, `home` 처럼 적어 보냅니다.

- **검사·작업 기록·결과 추적이 없는 1회성 직접 명령**입니다. 작업 목록에도 나오지 않습니다.
- 보내는 곳은 `/pinkyN/patrol_cmd` 하나입니다. `cmd_vel`·`goal_pose` 등 다른 토픽은 고를 수 없습니다.
- `allow_raw_cmd` 가 켜져 있을 때만 보입니다. **기본은 꺼짐**이고 가짜 핑키 launch 만 켭니다.
- 그 로봇에 진행 중이거나 결과를 모르는 관제 작업이 있으면 거절합니다. 먼저 정지하거나 해제합니다.
- 실물 도메인이면 보내기 전에 로봇 이름을 한 번 더 입력해야 합니다.
- 아래 로그는 실제로 나간 메시지 그대로입니다 (`/pinky1/patrol_cmd  std_msgs/msg/String  {data: "goto:P3,P7"}`). 줄에 마우스를 올리면 같은 메시지를 보내는 `ros2 topic pub --once …` 명령이 보입니다.
