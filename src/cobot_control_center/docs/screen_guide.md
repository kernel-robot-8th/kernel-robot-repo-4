# 관제 화면 사용법

화면을 여는 방법은 [README 화면 보기](../README.md#화면-보기), API·데이터 형식은 [api.md](api.md) 를 봅니다.

## 배치

```
┌ 상단 바: 도메인·모드 칩 · 백엔드·관제 노드·작업 노드 점 [작업 명령 켜기] · zone_manager·브릿지 점 · [전체 비상정지] ┐
│ 경고 띠 (경고가 있을 때만)                                                                     │
├──────────────────────────────┬──────────────────────────────────────────────┤
│ 지도                          │ 로봇 카드 (폭에 따라 1~3장 나란히)            │
│ 범례 (체크박스별 한 줄)        │ 작업 목록                                      │
│ 이벤트 로그                    │ 위험구역 A/B/C                                 │
│                              │ 개발: 수동 명령 (켜져 있을 때만)               │
└──────────────────────────────┴──────────────────────────────────────────────┘
```

좁은 화면에서는 한 줄로 쌓입니다.

화면의 시각은 모두 24시간 `HH:MM:SS` 입니다 (상단 갱신 시각, 이벤트 로그, 작업 목록, 수동 명령 로그).

## 상단 바

**백엔드**(WebSocket)·**관제 노드**(`fleet_status` 수신)·**작업 노드**(`fleet_control_node`) 점이 빨강이면 해당 연결이 끊긴 것입니다.
작업 노드 옆 **작업 명령 켜기 / 끄기** 버튼으로 작업 명령을 켜고 끕니다 ([작업 명령 켜기·끄기](#작업-명령-켜기끄기)).
제목 옆 칩은 지금 보는 도메인과 모드입니다. `도메인 100 · 실물` 이 아니면(가짜 핑키, 시험) 주황으로 표시합니다.
칩 끝에 `개발(읽기 전용)` 이 붙고 테두리가 점선이면 개발용 백엔드(8083) 화면입니다. 실물 데이터는 똑같이 보이지만 명령 버튼(정지 포함)은 모두 꺼져 있습니다. 명령은 실물 관제 화면(8080)에서 보냅니다.
그 옆 **zone_manager**·**브릿지 1 2 3** 점은 관제 PC 기반 노드 상태입니다 (마우스를 올리면 설명).

| 점 | 뜻 |
|---|---|
| 초록 | 정상 (하나 떠 있음) |
| 빨강 | 없음, 또는 **중복**(같은 도메인에 두 벌. zone_manager 가 둘이면 구역 판단이 갈라짐) |
| 주황 | 확인 불가. 위치를 내는 노드는 있지만 DDS 구현이 달라(예: Cyclone ↔ Fast DDS) 이름이 안 보임 |
| 회색 | 해당 없음(실물 도메인이 아님) 또는 관제 노드 끊김 |

경고가 있으면 상단 바 아래에 띠로 보입니다 (주황 주의, 빨강 위험). 배터리 부족, 연결 끊김, FAILED/STOPPED,
이동 중인데 오래 제자리(끼임 의심), 구역을 오래 점유한 경우입니다. 관제 노드가 끊기면 띠를 숨깁니다.

## 지도

위험구역을 겹쳐 그립니다. 주행 설정 파일(`pinkyN.yaml`, `zone_params.yaml`)을 읽기만 합니다.

| 표시 | 뜻 |
|---|---|
| 큰 원 + `A` | 구역 지점(`ZA` 등). 초록 비어 있음, 주황 점유, 회색 상태 모름. 원 크기는 표시용이며 실제 구역 넓이가 아님 |
| 빨간 × `A 출구` | `ZA_EXIT`. 구역을 나와 토큰을 반납하는 지점 |
| 빈 원 `A0`, `A1` .. | 대기 슬롯 (`A0` 이 맨 앞). 같은 자리의 슬롯은 `A0·B0` 처럼 합쳐 표시 |
| 마름모 `I1` .. | 로봇 홈 |
| 파란 점 + 선 `P1` .. | 일반 웨이포인트. 선은 도착 방향(yaw). 같은 자리는 `P1·P10` 처럼 합쳐 표시. `(0, 0, 0)` 인 P 지점은 미실측 예비값이라 숨기고 범례에 개수만 표시 |
| 로봇 색 알약 | 로봇 이름표 |

- 범례의 **구역 표시**(구역·출구·대기 슬롯·홈)와 **웨이포인트**(P) 체크박스로 따로 끄고 켭니다 (선택은 브라우저에 기억). 지점을 고르는 동안에는 꺼 둔 표시도 잠시 켜집니다.
- 지도에서 **로봇을 누르면** 그 로봇 카드로 스크롤하고 잠깐 강조합니다.
- 로봇마다 구역 좌표가 다르면 `fleet_api_node` 가 시작할 때 경고를 남깁니다.

## 이벤트 로그

state 변화, 연결·끊김, 구역 점유·해제, 경고 발생·해제를 시간순(최신이 위)으로 보여 주고 로봇별로 거를 수 있습니다.
백엔드 메모리에 최근 `events_max` 개만 두므로 백엔드를 다시 켜면 지워집니다.

## 로봇 카드

```
● pinky1  ▭ 91%                         연결    ← 이름 · 배터리 · 연결 배지
( 이동 중 )  MOVING  P3 · #0                     ← 상태 배지 · 원래 코드 · 설명
(0.30, 0.40) m · 90° · 수신 방금    [위치 복사]  ← 위치 · 마지막 수신
─────────────────────────────────────────────
🕹 명령 잠김: 로봇 작업 중 (MOVING)              ← 명령 바닥판: 명령을 보낼 수 있는지
[ 이동 ] [ 구역 ] [ 나가기 ] [ 홈 ]
[      정지      ] [     비상정지     ]
```

| 줄 | 뜻 |
|---|---|
| 배터리 | 30 % 이하 주황, 15 % 이하 빨강, 모르면 회색 `—` |
| 연결 배지 | `연결` / `끊김`(8초 이상 수신 없음) / `미수신`(켠 뒤 한 번도 못 받음) |
| 상태 배지 | 순찰 상태를 한글로. 색: 파랑 이동, 주황 대기, 초록 도착·완료, 빨강 실패·정지됨, 회색 유휴. 옆 작은 글이 원래 코드(MOVING 등)로, 이벤트 로그와 맞춰 볼 때 씀 |
| 상태 설명 | 순찰 노드 `detail` 그대로. `IDLE_WAIT 40` 은 유휴 복귀까지 설정된 시간 [s](카운트다운 아님), `#0` 은 경로 안에서 몇 번째 지점인지(0부터) |
| 위치 | x, y [m], yaw [°]와 마지막 수신 시간 |

길어진 글은 잘리고(…) 마우스를 올리면 전체가 보입니다.

### 위치 복사 (웨이포인트 실측)

로봇을 원하는 자리에 세운 뒤 **위치 복사**를 누르면 지금 위치 `[0.123, -0.456, 1.57]` (x, y [m], yaw [rad]) 가 클립보드에 들어갑니다.
`pinkyN.yaml` 의 `points` 값 형식과 같으므로 `P36: ` 뒤에 붙여 넣으면 됩니다. 서버에 저장하거나 로봇에 보내지 않고, 파일도 고치지 않습니다.
클립보드를 못 쓰는 환경이면 그 줄을 카드에 띄워 선택해 두므로 Ctrl+C 로 복사합니다.

다음이면 버튼에 `주의:` 가 뜹니다 (복사는 막지 않음): 이동 중, 연결 끊김, 위치를 받은 적 없음,
amcl 표준편차가 `teach_max_std_xy`·`teach_max_std_yaw` 초과.
amcl 은 로봇이 멈춰 있으면 위치를 새로 내지 않으므로 마지막 추정값을 씁니다.

## 명령 보내기

명령은 작업 노드 `fleet_control_node` 가 켜져 있고 **작업 명령**이 켜져 있어야 보낼 수 있습니다 ([README 명령 켜기](../README.md#명령-켜기)). 실물 도메인이면 실물 로봇이 움직입니다.

### 작업 명령 켜기·끄기

버튼 글은 **누르면 할 일**이고, 색이 지금 상태입니다.

| 버튼 | 지금 상태 | 누르면 |
|---|---|---|
| `작업 명령 켜기` (회색 테두리) | 꺼짐: 이동·구역·나가기·홈과 수동 명령이 막힘 | 확인 창 `실물 로봇이 움직입니다 (도메인 100)` → 켜짐 |
| `작업 명령 끄기` (주황) | 켜짐: 작업 명령을 보낼 수 있음 | 확인 없이 바로 꺼짐 |

- 작업 노드는 bringup 과 함께 켜지지만 **작업 명령 꺼짐**으로 시작합니다. 작업 노드가 재시작해도 다시 꺼집니다. 시험이 끝나면 꺼 둡니다.
- 정지·비상정지·전체 비상정지·결과 모름 해제는 꺼져 있어도 됩니다.
- 켜기·끄기는 작업 노드 기록(`operator_arm`)에 누른 PC 의 IP 와 함께 남습니다.

### 명령 바닥판

카드의 첫 줄(조이스틱 아이콘)이 지금 명령을 보낼 수 있는지 알려 줍니다.

| 표시 | 색 | 뜻 |
|---|---|---|
| `명령 가능` · `명령 가능 · A 보유 중` | 초록 | 보낼 수 있음 (잡고 있는 구역이 있으면 함께 표시) |
| `작업 중: goto:P3,P7 · 진행 · P3` | 파랑 | 관제가 보낸 작업이 진행 중 |
| `결과 모름: zone:ZA · 눌러서 현장 확인 후 해제` | 빨강 | 결과를 모르는 작업이 있어 해제 전까지 새 명령 막힘. 누르면 해제 확인이 열림 |
| `명령 잠김: 상단 '작업 명령 켜기'를 누르세요` | 주황 | 작업 명령이 꺼져 있음 ([작업 명령 켜기·끄기](#작업-명령-켜기끄기)) |
| `명령 잠김: 로봇 작업 중 (MOVING)` 등 | 주황 | 작업 노드 꺼짐, 연결 끊김, 로봇이 스스로 움직이는 중(유휴 복귀 등) |

명령을 보낸 직후 잠깐 이 줄에 결과가 나옵니다 (`보냄: goto:P3 (t-…)` 초록, `이동 거절 (409): …` 빨강).

누를 수 있는 버튼은 파란 글자, 잠긴 버튼은 흐린 회색입니다. **나가기**는 잡은 구역이 없으면 꺼집니다 (구역 상태를 모르면 막지 않음). 구역을 잡고 있어도 **이동**·**구역**은 켜져 있고, 보내면 로봇이 먼저 구역을 나간 뒤 갑니다. 이동을 끝내고 홈 복귀를 기다리는 동안에도 다음 명령을 보낼 수 있습니다 (2026-11-09).

### 이동 · 구역 · 나가기 · 홈

누르면 그 카드 위에 **지점 고르기**가 덮입니다 (아래 정지 줄은 가리지 않음).

- 이동: 지도에서 P 점을 차례로 누르거나 이름 버튼으로 골라 경로를 만듭니다. 고른 지점에 순번(1, 2 ..)이 붙고, 지도에 로봇 위치부터 경로를 미리 그립니다.
- 구역: 구역 지점 하나를 고릅니다. 홈·나가기는 고를 지점 없이 확인만 합니다.
- 고른 경로(`P3 → P7`)를 확인하고 **보내기**. 취소는 **취소** 또는 Esc. 실물 도메인이면 경고가 뜹니다.
- 지점 목록(`/api/map/layers`)이 없으면 이름을 직접 적습니다 (`P1, P2`).

### 정지 · 비상정지

- 카드 맨 아래 줄에 있고(정지 = 빨간 테두리, 비상정지 = 꽉 찬 빨강), **확인 창 없이 바로** 보냅니다. 작업 노드가 살아 있으면 언제나 누를 수 있습니다.
- 정지는 그 로봇만 멈추고 **잠그지 않습니다**. 바로 다음 명령을 보낼 수 있습니다. 구역 안이면 구역 밖으로 물러나 토큰을 풉니다. 그 로봇에 주문이 걸려 있으면 비상정지처럼 제자리에 서고 보류됩니다 (2026-11-09).
- 비상정지(`estop`)는 구역 토큰을 쥔 채 그 자리에 멈추고 **그 로봇만 보류됩니다** (다른 로봇과 작업 명령은 그대로). [제어권 복구](#제어권-복구-정지-잠금-해제) 뒤에 다시 명령을 받습니다. 상단 **전체 비상정지**만 작업 명령 전체를 끕니다.
- 상단 바 **전체 비상정지**는 로봇 지정 없는 `estop` 한 번으로 모든 로봇·팔을 세웁니다. 작업 노드가 꺼져 있으면 눌리지 않습니다.

### 위험구역 칸

구역마다 점유 로봇과 대기열(`대기 pinky2 → pinky3`, 앞 순번부터)을 보여 줍니다.

### 작업 목록

관제가 보낸 명령 기록입니다. 한 줄에 `시각 · 로봇 · 명령(이동 P3→P7) · 결과 · 이유/걸린 시간` 이고, 작업 번호·규격(v1/v2)·원래 명령은 마우스를 올리면 보입니다.

- **결과 모름**(빨강)·**진행 중**(파랑)은 맨 위에 고정됩니다.
- 제목 옆에 `진행 N · 결과 모름 N` 요약, 오른쪽에 로봇 필터가 있습니다. 최근 50개까지 봅니다.
- 로봇이 혼자 하는 순찰·유휴 복귀는 관제 명령이 아니라 여기 나오지 않습니다 (이벤트 로그에서 봄).

### 결과 모름 해제

결과 모름은 로봇이 실제로 움직이고 있을 수 있다는 뜻이라, 해제 전에는 그 로봇에 새 명령을 보내지 않습니다 (왜 생기는지는 [api.md 작업·주문](api.md#작업주문-fleet_control_node)).

1. 현장에서 로봇이 멈춘 것을 확인합니다.
2. 작업 줄의 **현장 확인 후 해제** 또는 카드의 빨간 결과 모름 줄을 누르면 그 카드 위에 **해제 확인**이 덮입니다.
3. 확인 내용을 적고 **현장 확인함 · 해제**를 누르면 실패로 기록되고 다시 명령을 받습니다. 취소는 Esc.

그 로봇이 **정지 잠금(보류)** 중이면 해제 대신 **제어권 복구** 띠가 뜨고, 버튼 글도 **현장 확인 후 복구**로 바뀝니다. 해제(fleet `resolve`)는 로봇이 재부팅해 잠금이 풀린 채 올라오면 거절될 수 있어, 보류 중일 때는 복구 하나로 보류와 결과 모름을 같이 풉니다.

### 제어권 복구 (정지 잠금 해제)

카드 상태 줄이 빨간 **정지 잠금**이면 (비상정지·주문 중 정지·하트비트 끊김·관제 재시작 뒤) 그 줄을 누릅니다. 현장 확인 체크(멈춤·팔·화물)·운영자·메모를 넣고 **현장 확인함 · 복구**를 누릅니다. 결과 모름 작업이 함께 있어도 복구 하나로 같이 풀립니다 (결과 모름은 실패로 기록). 전체 비상정지 뒤라면 작업 명령이 꺼져 있으니 상단에서 다시 켭니다. 구역 안에서 잠긴 경우도 복구할 수 있습니다. 복구한 뒤 **나가기**로 빼냅니다 (그때까지 다른 로봇은 그 구역에 못 들어옴).

### 수동 상차 확인

팔이 연결되지 않았거나 실패해서 주문이 상차장에서 멈추면, 그 로봇 카드 상태 줄이 빨간 **상차 확인 대기 · 주문 o1 (box_a) · 눌러서 현장 확인** 이 됩니다 (상차장 도착 뒤 상차 검증 단계의 주문만).

1. 현장에서 주문 상품(SKU)을 로봇에 직접 싣습니다. 로봇팔이 물러나 있고, 로봇 뒤 통로가 비어 있는지 봅니다.
2. 상태 줄을 누르면 **수동 상차 확인** 띠가 뜹니다. **현장 확인: 적재됨·팔 퇴피·통로 비움**을 체크하고 운영자 이름을 넣습니다 (이름은 이 브라우저에 기억됨). 메모는 기록에 남습니다.
3. **현장 확인함 · 상차 완료**를 누르면 fleet 이 상차장 도착·정지·통신·구역·예약을 검사하고, 통과하면 로봇이 **상차 구역 이탈부터** 이어서 갑니다. 거절되면 fleet 이 낸 이유가 상태 줄에 잠깐 보입니다. 취소는 Esc.

보류 중인 로봇의 결과 모름은 복구로, 보류 없는 결과 모름은 해제로 먼저 풀고, 상차 확인은 정지 잠금 복구보다 먼저 뜹니다 (fleet 이 상차 확인을 받으면 잠금도 풉니다).

## 로봇 상세 화면

로봇 카드 오른쪽 위의 **상세 ›** 버튼(또는 이름)을 누르면 그 로봇 한 대만 보는 화면으로 바뀝니다 (주소 `#/robot/pinky1`, 북마크·새로 고침 가능).
**← 전체** 또는 브라우저 뒤로 가기로 돌아갑니다. 상단 바와 경고 띠는 두 화면이 같이 씁니다.

```
┌ ← 전체  ● pinky1 [연결] (이동 중) 배터리 72%      명령 가능                       ┐
│                                              [이동][구역][나가기][홈] [정지][비상정지] │  ← 스크롤해도 위에 붙음
├───────────────────────────────────┬────────────────────────────┤
│ 카메라 (크게)                       │ 지도: 이 로봇 중심 확대 [＋][－] │
│                                   │ 진행 중 경로 점선 · 다른 로봇 흐리게 │
├────────────┬────────────┬────────────┬────────────┤
│ 현재 작업    │ 위치        │ 구역        │ 최근 작업    │
├───────────────────────────────────┬────────────────────────────┤
│ 타임라인 (작업 + 상태 변화, 최신 위) │ 진단 (마지막 수신) · 추가 필드  │
└───────────────────────────────────┴────────────────────────────┘
```

| 칸 | 뜻 |
|---|---|
| 상태줄 | 연결·상태·배터리와 명령 버튼. 명령 버튼·잠김 이유·결과 메시지는 카드와 같습니다. 이동·구역을 누르면 지점 고르기 띠가 상태줄 바로 아래에 열리고, 지점은 띠의 버튼이나 확대 지도를 눌러 고릅니다 |
| 카메라 | 로봇 카메라 영상 (`camera_topic_format` 토픽의 JPEG). 3초 넘게 새 프레임이 없으면 `영상 없음 · 마지막 수신 N초 전`, 받은 적이 없으면 `영상 없음 (아직 받은 적 없음)`. 다시 들어오면 저절로 다시 붙음 |
| 지도 | 이 로봇을 가운데로 확대 (＋ 0.8 m · 기본 1.4 m · － 전체). 진행 중 작업의 경로를 점선과 순번으로 그림. 다른 로봇을 누르면 그 로봇 상세로 |
| 요약 | 현재 작업(진행·결과 모름), 위치(x, y, yaw, 웨이포인트), 구역(점유·대기 순번), 최근 작업(받은 작업 목록 안의 성공·실패 수, 하루 전체 집계 아님) |
| 타임라인 | 이 로봇의 상태 변화 이벤트와 작업 결과를 시간순(최신 위)으로 합침. 최근 50줄 |
| 진단 | 연결·위치·배터리·순찰 상태·카메라의 마지막 수신 시간. 8초 안 초록, 30초 안 주황, 넘으면 빨강, 받은 적 없으면 회색 (실물 배터리는 5초 주기, 서 있는 로봇은 위치를 잘 안 냄). 명령 규격 v1/v2, 순찰 노드 추가 필드(`command_id` 등) |

- **로봇 직접 조종(방향키 등)은 없습니다.** 웹·브릿지·와이파이를 거치는 지연과 끊김, 순찰 노드·Nav2 와의 `cmd_vel` 충돌 때문입니다. 현장에서 옮길 때는 로봇 근처에서 `teleop_twist_keyboard` 를 씁니다.
- 실물 카메라는 브릿지(`cobot_domain_bridge`)에 카메라 토픽이 들어가야 보입니다. 그 전에는 실물에서 늘 `영상 없음` 입니다.
- 없는 로봇 이름이면 `등록되지 않은 로봇입니다` 만 보입니다.

## 개발용 수동 명령

순찰 노드에 문자열을 그대로 보내 보는 칸입니다. 오른쪽 칸 맨 아래 **"개발: 수동 명령"** 을 펼쳐 로봇을 고르고 `goto:P3,P7`, `home` 처럼 적어 보냅니다.

- **검사·작업 기록·결과 추적이 없는 1회성 직접 명령**입니다. 작업 목록에도 나오지 않습니다.
- 보내는 곳은 `/pinkyN/patrol_cmd` 하나입니다. `cmd_vel`·`goal_pose` 등 다른 토픽은 고를 수 없습니다.
- `allow_raw_cmd` 가 켜져 있을 때만 보입니다. **기본은 꺼짐**이고 가짜 핑키 launch 만 켭니다.
- 그 로봇에 진행 중이거나 결과를 모르는 관제 작업이 있으면 거절합니다. 먼저 정지하거나 해제합니다.
- 실물 도메인이면 보내기 전에 로봇 이름을 한 번 더 입력해야 합니다.
- 아래 로그는 실제로 나간 메시지 그대로입니다 (`/pinky1/patrol_cmd  std_msgs/msg/String  {data: "goto:P3,P7"}`). 줄에 마우스를 올리면 같은 메시지를 보내는 `ros2 topic pub --once …` 명령이 보입니다.
