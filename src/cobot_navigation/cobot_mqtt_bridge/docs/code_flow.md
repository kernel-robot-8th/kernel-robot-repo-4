# code_flow — 코드가 하는 일 (쉬운 설명)

코드를 처음 읽는 사람을 위한 안내서입니다. 괄호 안의 이름은 코드에서 찾을 때 쓰는 함수·파일 이름이니, 이해하는 데는 몰라도 됩니다. 모르는 용어는 맨 아래 [용어 풀이](#8-용어-풀이)에 있습니다.

## 1. 이 프로그램이 하는 일

**로봇과 관제 PC는 서로 직접 말하지 않습니다. 중간에 우체국(MQTT 브로커)을 두고, 편지를 대신 전달해 주는 프로그램입니다.**

```
로봇 쪽 프로그램  ──편지──>  우체국(브로커)  ──편지──>  관제 쪽 프로그램
 (로봇 안에서 실행)                               (관제 PC에서 실행)
```

- 편지 내용은 로봇의 정보입니다. 위치, 배터리, 라이다 값 같은 것입니다.
- 반대로 관제가 로봇에게 보내는 편지도 있습니다. "P1로 가라" 같은 명령입니다.

## 2. 프로그램은 하나, 역할은 두 가지

같은 코드를 **로봇에서 켜면 로봇 쪽**, **관제 PC에서 켜면 관제 쪽**으로 움직입니다. 둘이 하는 일은 대칭입니다.

| 하는 일 | 설명 |
|---|---|
| **보내는 쪽** | 자기 쪽 ROS에서 값을 듣고 → 편지로 포장해 → 우체국에 맡긴다 |
| **받는 쪽** | 우체국에서 편지를 받아 → 포장을 풀어 → 자기 쪽 ROS에 내보낸다 |

누가 어느 쪽인지는 방향에 따라 정해집니다.

| 편지 종류 | 보내는 쪽 | 받는 쪽 | 예 |
|---|---|---|---|
| **값** (로봇 → 관제, 코드에서는 `up`) | 로봇 | 관제 PC | 위치, 배터리 |
| **명령** (관제 → 로봇, 코드에서는 `down`) | 관제 PC | 로봇 | `patrol_cmd` |

## 3. 어떤 파일이 무슨 일을 하나

| 파일 | 한 줄 설명 |
|---|---|
| `mqtt_bridge_node.py` | **본체.** 위 일을 실제로 한다. 나머지 3개를 불러서 쓴다. |
| `bridge_config.py` | "어떤 토픽을 어느 방향으로 전달할지" 적힌 목록(YAML)을 읽는다. |
| `relay_utils.py` | 편지 포장·풀기, 너무 잦은 전송 줄이기, **잘못된 곳에 보내지 않는지 검사.** |
| `cmd_vel_guard.py` | 로봇 속도 명령의 **안전장치.** |

## 4. 켜면 일어나는 일 (시작)

순서대로 5단계입니다. 문제가 있으면 이유를 화면에 쓰고 바로 끝납니다.

1. **준비** (`prepare`): 설정을 확인하고, 전달할 토픽 목록을 만든다.
2. **안전 검사** (준비 안에서): "여기에 보내도 되는 곳인가?"를 확인한다.
   - 확인 없이 실제 로봇 도메인에 명령을 보내려 하면 막는다.
   - 속도 제한이 꺼져 있으면 실제 로봇에서는 시작하지 않는다.
3. **ROS 연결** (`build_ros`): 토픽마다 "듣는 귀"(구독자) 또는 "말하는 입"(발행자)을 만든다.
4. **우체국 접속** (`connect`): 브로커에 접속한다. 이때 "내가 갑자기 죽으면 대신 '죽었다'고 알려 달라"는 **유언**을 맡겨 둔다.
5. **반복 시작** (`run`): 감시를 하면서 계속 전달한다.

## 5. 편지 하나가 가는 길

### 값이 올라갈 때 (예: 로봇의 위치 `/odom`)

**로봇 쪽 (보내는 쪽):**
1. 로봇 ROS가 위치 값을 낸다.
2. 프로그램이 받는다 (`_on_ros_message`).
3. 너무 자주 오면 일부 버린다. (센서 값은 곧 새 값이 오니 괜찮다)
4. 편지 봉투(JSON)에 넣는다. 봉투에는 **종류, 보낸 시각, 내용**이 들어 있다.
5. 우체국이 연결되어 있을 때만 맡긴다. 끊겨 있으면 버린다.

**관제 쪽 (받는 쪽):**
1. 우체국에서 편지가 온다 (`_on_mqtt_message`).
2. 봉투를 열어 종류가 맞는지 확인한다.
3. ROS 메시지로 되돌려 관제 ROS에 내보낸다. 이름은 `/pinky1/odom`처럼 로봇 이름이 붙는다.

### 명령이 내려갈 때 (예: `patrol_cmd`)

길은 같고 방향만 반대입니다. 다른 점은 두 가지입니다.
- 명령은 **한 번이라도 빠지면 안 되어서** 더 확실한 배달 방식(QoS 1)을 씁니다. 값은 놓쳐도 다음 값이 오니 가벼운 방식(QoS 0)을 씁니다.
- 명령은 **기본으로 꺼져 있습니다.** `mode:=cmd`로 켜야만 열립니다. 로봇이 움직일 수 있기 때문입니다.

## 6. 로봇 속도 명령의 안전장치 3개

속도 명령(`cmd_vel`)은 로봇을 직접 움직이므로 받을 때마다 3가지를 확인합니다 (`cmd_vel_guard.py`).

| 안전장치 | 막는 일 | 비유 |
|---|---|---|
| **오래된 명령 버리기** | 네트워크가 느려 늦게 도착한 명령으로 움직이는 것 | 어제 온 "출발해"는 무시 |
| **속도 상한** | 너무 큰 속도 값이 와서 로봇이 확 튀는 것 | 최고 시속 제한 |
| **워치독** | 연결이 끊긴 채 마지막 속도로 계속 달리는 것 | 운전자가 손을 놓으면 자동 정지 |

- 속도 상한은 방향은 그대로 두고 크기만 줄입니다. 예를 들어 상한이 0.15인데 0.30이 오면 0.15로 줄입니다.
- 워치독은 마지막 명령 뒤 정해진 시간이 지나면 **정지 명령을 한 번** 보냅니다. 연결이 끊기면 기다리지 않고 바로 보냅니다.
- 오래된 명령 버리기는 기본이 꺼져 있습니다. 두 장비의 시계가 맞아야 정확하기 때문입니다.

## 7. 문제가 생기면, 그리고 끝날 때

| 상황 | 프로그램이 하는 일 |
|---|---|
| 우체국과 연결이 끊김 | 로봇이 움직이는 중이면 바로 정지. 다시 연결되면 자동으로 이어 붙는다. |
| 명령이 한동안 안 옴 | 워치독이 정지 명령을 한 번 보낸다. |
| 프로그램이 갑자기 죽음 | 우체국이 맡아 둔 유언대로 "죽었다"(`cause=will`)고 알려 준다. |
| 실행을 시킨 쪽(launch, ssh)이 사라짐 | 혼자 남지 않고 스스로 종료한다. |
| 로봇이 너무 바쁨(부하 과다) | 스스로 멈춰서 로봇을 보호한다. |
| Ctrl+C로 끔 | 움직이는 중이면 정지 → 결과 요약 → "끝났다"(`cause=exit`)고 알리고 종료. |

종료할 때 화면에 나오는 **종료 코드**는 이렇습니다.
- `0`: 한 건 이상 전달하고 정상 종료
- `1`: 한 건도 전달하지 못했거나 스스로 멈춤
- `2`: 시작 전 설정, 접속, 안전 검사에서 실패

## 8. 용어 풀이

| 용어 | 쉬운 뜻 |
|---|---|
| **ROS 토픽** | 로봇 프로그램끼리 값을 주고받는 "게시판 이름". 예: `/odom` |
| **도메인 (ROS_DOMAIN_ID)** | ROS 게시판을 나누는 "방 번호". 로봇은 10번 방, 관제는 200번 방. 다른 방끼리는 안 보인다. |
| **MQTT / 브로커** | 편지를 중간에서 받아 전달하는 우체국과 그 방식. |
| **QoS 0 / 1** | 배달 확실도. 0은 놓칠 수 있지만 가볍고, 1은 반드시 도착한다. |
| **retain** | 우체국이 마지막 편지를 보관해 두는 것. 나중에 접속한 쪽도 최신 값을 받는다. |
| **유언 (will)** | 프로그램이 갑자기 죽으면 우체국이 대신 알려 주는 메시지. |
| **워치독** | 일정 시간 소식이 없으면 자동으로 정지시키는 감시기. |
| **source / sink** | 코드에서 부르는 이름. source는 "보내는 쪽", sink는 "받는 쪽". |

## 9. 고치고 싶을 때

대부분은 **코드를 고치지 않고 설정 파일만** 고치면 됩니다.

| 하고 싶은 일 | 고칠 곳 |
|---|---|
| 전달할 토픽 추가·삭제 | `config/mqtt_topics_pinky1~3.yaml` |
| 너무 잦은 토픽 줄이기 | `config/mqtt_bridge.yaml`의 `rate_limits` |
| 속도 상한, 워치독 시간 | `config/mqtt_down.yaml` |
| 전달에서 뺄 토픽 | `exclude_patterns` (`mqtt_bridge.yaml`, `mqtt_down.yaml`) |
| 실행 방법(launch) | `launch/mqtt_bridge.launch.xml` |
| 안전 규칙 자체 | `relay_utils.py`, `cmd_vel_guard.py` (**신중하게, 시험 도메인에서 먼저 확인**) |

토픽을 바꾼 뒤에는 `python3 -m pytest test -q`를 돌려 주세요. 시험이 토픽 개수를 확인하므로, 숫자가 바뀌면 시험도 함께 고쳐야 할 수 있습니다.
